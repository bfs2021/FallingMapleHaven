# 默契问答插件重构技术契约

> 版本: v1.0  
> 状态: 已收敛待开发  
> 前置产品文档: `Docs/12-默契问答插件重构产品需求文档.md`  
> 面向读者: 前端、后端、测试、代码审查  
> 目标: 固定新版默契问答插件的数据字段、接口、枚举、权限、错误码、前端路由和一致性规则，后续开发必须按本文执行。

---

## 1. 总体约定

### 1.1 新旧版本关系

新版默契问答不兼容旧版“好友单题出题”接口。

必须废弃旧语义：

- 用户给好友单独出一道题。
- 好友收到单题邀请。
- 好友答单题后更新两人累计匹配度。
- `/plugins/quiz/questions/` 旧出题语义。
- `/plugins/quiz/questions/received/` 旧收题语义。
- `/plugins/quiz/result/{friend_id}/` 旧好友结果语义。
- `/plugins/quiz/leaderboard/` 旧好友排行榜语义。

旧测试数据处理：

- 旧版数据均为测试数据。
- 不做数据迁移。
- 实施新版时可以删除旧表数据或随迁移重建模型。
- 不要求保留旧接口兼容。

### 1.2 API 基础规范

所有新版接口基础路径：

```text
/api/v1/plugins/quiz/
```

所有响应必须使用项目统一格式：

```json
{
  "code": 0,
  "message": "success",
  "data": {}
}
```

分页响应必须使用统一结构：

```json
{
  "total": 100,
  "page": 1,
  "page_size": 20,
  "results": []
}
```

前端 axios 已在 `frontend/src/api/client.js` 中将响应解包为响应体，因此前端 API 使用时读取 `res.data`。

### 1.3 认证规范

| 场景 | 认证要求 |
|------|----------|
| 主页公开测试列表 | 允许未登录访问 |
| 已发布测试详情 | 允许未登录访问 |
| 提交答卷 | 允许未登录访问 |
| 我的测试管理 | 必须登录且为测试 owner |
| 我答过的 | 必须登录 |
| 系统题库列表 | 登录用户创建测试时必须登录；如仅答题页不需要题库 |
| 管理后台接口 | 必须登录且为管理员 |

### 1.4 CSRF 与 Cookie

项目使用 Django Session + CSRF。

未登录访客提交答卷时仍然是 unsafe method，前端必须按现有 axios 拦截器获取并携带 CSRF。

访客标识 Cookie：

| 项 | 约定 |
|----|------|
| Cookie 名称 | `fmh_visitor_id` |
| 有效期 | 1 年 |
| 用途 | 未登录访客同浏览器防重复答题 |
| 生成方 | 后端 |
| 设置时机 | 未登录访客访问答题页详情接口或提交答卷时，如不存在则生成 |
| 存储要求 | 数据库中不得保存 Cookie 明文；必须保存 Cookie 值哈希 |
| 前端使用 | 前端不需要手动读写该 Cookie |

## 2. 枚举与常量

### 2.1 测试状态 `QuizTestStatus`

| 值 | 含义 | 前台可见 | 可编辑题目 | 可提交答卷 |
|----|------|----------|------------|------------|
| `draft` | 草稿 | 否 | 是 | 否 |
| `published` | 已发布 | 是 | 否 | 是 |
| `deleted` | 已删除 | 否 | 否 | 否 |

实现要求：

- 普通用户删除测试时，将状态置为 `deleted`。
- 管理员删除测试时，也默认置为 `deleted`。
- 删除为业务软删，不物理删除业务数据。

### 2.2 参与者类型 `QuizParticipantType`

| 值 | 含义 |
|----|------|
| `user` | 登录用户 |
| `visitor` | 未登录访客 |

### 2.3 题型 `QuizQuestionType`

首版只允许：

| 值 | 含义 |
|----|------|
| `single_choice` | 单选题 |

### 2.4 题目数量与选项数量

| 常量 | 值 |
|------|----|
| `MAX_TESTS_PER_OWNER` | 3 |
| `PUBLISHED_QUESTION_COUNT` | 10 |
| `MIN_OPTIONS_PER_QUESTION` | 2 |
| `MAX_OPTIONS_PER_QUESTION` | 4 |

### 2.5 文本长度限制

首版采用轻量文本限制，前后端必须使用同一组限制。

| 字段 | 最大长度 |
|------|----------|
| 测试标题 `title` | 30 个字符 |
| 题目文案 `question_text` | 80 个字符 |
| 选项文案 `option_text` | 30 个字符 |
| 访客昵称 `participant_name` | 12 个字符 |

### 2.6 称号分段

首版必须写死以下分段，不提供后台配置。

| 答对题数 | 正确率 | 称号 |
|----------|--------|------|
| 10 | 100% | 灵魂拍档 |
| 8-9 | 80%-90% | 很懂 TA |
| 6-7 | 60%-70% | 默契在线 |
| 4-5 | 40%-50% | 还要多聊聊 |
| 0-3 | 0%-30% | 神秘距离感 |

字段名统一使用：

```text
title
```

不要使用 `rank_title`、`badge`、`level_name` 等其他字段名。

## 3. 数据模型契约

本节定义逻辑模型和字段契约。Django 实现可根据项目习惯添加 `BigAutoField`、索引、`created_at`、`updated_at` 等字段，但不能改变对外字段语义。

### 3.1 `QuizTest` 测试表

约定表名：

```text
plugins_quiztest
```

字段：

| 字段 | Django 字段类型 | 必填 | 说明 |
|------|----------|------|------|
| `id` | BigAutoField | 是 | 测试 ID |
| `owner` | FK(User) | 是 | 主页主人 |
| `title` | CharField(30) | 是 | 测试标题，最大 30 个字符 |
| `status` | CharField | 是 | `draft` / `published` / `deleted` |
| `created_at` | DateTime | 是 | 创建时间 |
| `updated_at` | DateTime | 是 | 更新时间 |
| `published_at` | DateTime(null=True) | 否 | 发布时间 |
| `deleted_at` | DateTime(null=True) | 否 | 删除时间 |

约束：

- 同一 `owner` 下，`status != deleted` 的测试最多 3 套。
- `published` 状态测试必须有且只有 10 道未删除题目。
- `published` 状态测试不可修改题目、选项、标准答案。
- `deleted` 状态测试前台不可见、不可答题。

必须建立索引：

- `(owner, status)`
- `(status, published_at)`

### 3.2 `QuizTestQuestion` 测试题目表

约定表名：

```text
plugins_quiztestquestion
```

字段：

| 字段 | Django 字段类型 | 必填 | 说明 |
|------|----------|------|------|
| `id` | BigAutoField | 是 | 题目 ID |
| `test` | FK(QuizTest) | 是 | 所属测试 |
| `question_type` | CharField | 是 | 首版固定 `single_choice` |
| `question_text` | CharField(80) | 是 | 题目文案，最大 80 个字符 |
| `order` | PositiveIntegerField | 是 | 题目顺序，从 1 开始 |
| `correct_option` | FK(QuizTestOption, null=True) | 否 | 主页主人标准答案，发布时必填 |
| `source_bank_question` | FK(QuizQuestionBank, null=True) | 否 | 来源题库题，可为空 |
| `created_at` | DateTime | 是 | 创建时间 |
| `updated_at` | DateTime | 是 | 更新时间 |

约束：

- 同一测试内 `order` 唯一。
- 发布时题目数量必须正好 10。
- 发布时每题 `correct_option` 必须属于当前题目的选项。

必须建立索引：

- `(test, order)`

### 3.3 `QuizTestOption` 测试选项表

约定表名：

```text
plugins_quiztestoption
```

字段：

| 字段 | Django 字段类型 | 必填 | 说明 |
|------|----------|------|------|
| `id` | BigAutoField | 是 | 选项 ID |
| `question` | FK(QuizTestQuestion) | 是 | 所属题目 |
| `option_text` | CharField(30) | 是 | 选项文案，最大 30 个字符 |
| `order` | PositiveIntegerField | 是 | 选项顺序，从 1 开始 |
| `created_at` | DateTime | 是 | 创建时间 |
| `updated_at` | DateTime | 是 | 更新时间 |

约束：

- 同一题目内 `order` 唯一。
- 发布时每题必须有 2-4 个选项。
- 发布后不可修改。

必须建立索引：

- `(question, order)`

### 3.4 `QuizSubmission` 答卷表

约定表名：

```text
plugins_quizsubmission
```

字段：

| 字段 | Django 字段类型 | 必填 | 说明 |
|------|----------|------|------|
| `id` | BigAutoField | 是 | 答卷 ID |
| `test` | FK(QuizTest) | 是 | 所属测试 |
| `participant_type` | CharField | 是 | `user` / `visitor` |
| `user` | FK(User, null=True) | 否 | 登录用户，访客为空 |
| `participant_name` | CharField(30) | 是 | 展示昵称；登录用户为提交时账户昵称快照，访客为填写昵称。访客填写昵称最大 12 个字符 |
| `visitor_token_hash` | CharField(128, null=True) | 否 | 访客 Cookie 标识哈希，登录用户为空 |
| `correct_count` | PositiveIntegerField | 是 | 答对题数，0-10 |
| `score_percent` | DecimalField(5,2) | 是 | 正确率，例如 80.00 |
| `title` | CharField(50) | 是 | 称号 |
| `is_deleted` | BooleanField | 是 | 管理员软删答卷时置 true |
| `created_at` | DateTime | 是 | 提交时间 |

约束：

- 登录用户：同一 `test + user` 只能有一条未删除答卷。
- 未登录访客：同一 `test + visitor_token_hash` 只能有一条未删除答卷。
- `participant_name` 存提交时快照，不随用户后续改昵称变化。
- 普通前台列表不返回 `visitor_token_hash`。

必须建立索引：

- `(test, is_deleted, score_percent, correct_count, created_at)`
- `(test, user)`
- `(test, visitor_token_hash)`

### 3.5 `QuizSubmissionAnswer` 答卷单题答案表

约定表名：

```text
plugins_quizsubmissionanswer
```

字段：

| 字段 | Django 字段类型 | 必填 | 说明 |
|------|----------|------|------|
| `id` | BigAutoField | 是 | 答案 ID |
| `submission` | FK(QuizSubmission) | 是 | 所属答卷 |
| `question` | FK(QuizTestQuestion) | 是 | 对应题目 |
| `selected_option` | FK(QuizTestOption) | 是 | 参与者选择的选项 |
| `is_correct` | BooleanField | 是 | 是否与标准答案一致 |
| `created_at` | DateTime | 是 | 创建时间 |

约束：

- 同一 `submission + question` 只能有一条记录。
- 所有 `question` 必须属于 `submission.test`。
- 所有 `selected_option` 必须属于对应 `question`。
- 首版普通前台不暴露该表详情。
- 后台可以查看该表，用于追溯和后续扩展。

### 3.6 `QuizQuestionBank` 系统题库表

约定表名：

```text
plugins_quizquestionbank
```

字段：

| 字段 | Django 字段类型 | 必填 | 说明 |
|------|----------|------|------|
| `id` | BigAutoField | 是 | 题库题 ID |
| `question_text` | CharField(80) | 是 | 题目文案，最大 80 个字符 |
| `tags` | JSONField(default=list) | 否 | 标签数组，类型为 `string[]`，首版后台直接编辑标签文本 |
| `created_at` | DateTime | 是 | 创建时间 |
| `updated_at` | DateTime | 是 | 更新时间 |

题库题没有标准答案。标准答案只存在于用户测试副本中。

### 3.7 `QuizQuestionBankOption` 系统题库选项表

约定表名：

```text
plugins_quizquestionbankoption
```

字段：

| 字段 | Django 字段类型 | 必填 | 说明 |
|------|----------|------|------|
| `id` | BigAutoField | 是 | 题库选项 ID |
| `bank_question` | FK(QuizQuestionBank) | 是 | 所属题库题 |
| `option_text` | CharField(30) | 是 | 选项文案，最大 30 个字符 |
| `order` | PositiveIntegerField | 是 | 选项顺序，从 1 开始 |

约束：

- 每个题库题必须有 2-4 个选项。
- 题库题复制到测试时，必须复制题目和选项为测试副本。

```json
{
  "id": 101,
  "option_text": "蓝色",

}
```

### 4.3 `QuizQuestionPublic`

公开答题用题目对象，不能包含标准答案。

```json
  "question_text": "我最喜欢的颜色是？",
```

主人管理或后台查看用题目对象，可以包含标准答案。

```json
{
  "id": 11,
  "question_type": "single_choice",
  "question_text": "我最喜欢的颜色是？",
  "order": 1,
  "correct_option_id": 101,
  "source_bank_question_id": 5,
  "options": [
    { "id": 101, "option_text": "蓝色", "order": 1 },
    { "id": 102, "option_text": "红色", "order": 2 }
  ]
```

### 4.5 `QuizTestCard`

测试列表卡片对象。

```json
{
  "id": 1,
  "owner": {
    "user_id": 2,
    "username": "bob",
    "nickname": "Bob",
    "avatar_url": null
  },
  "title": "你有多了解我？",
  "status": "published",

  "published_at": "2026-07-12T12:10:00Z"

```

字段说明：

- `has_submitted` 对登录用户和有 `fmh_visitor_id` 的访客有效。
- 如果无法判断访客是否答过，返回 `false`。

### 4.6 `QuizTestDetailPublic`

```json
  "updated_at": "2026-07-12T12:05:00Z",

  "questions": []

```

### 4.8 `QuizSubmissionSummary`

答卷榜和我的结果使用。

```json
{
  "id": 123,
  "rank": 1,
  "is_tied": false,
  "participant_type": "user",
  "participant_name": "Alice",
  "user": {
    "user_id": 1,
    "username": "alice",
    "nickname": "Alice",
    "avatar_url": null
  },
  "correct_count": 8,
  "total_count": 10,
  "score_percent": 80.0,
  "title": "很懂 TA",
  "is_current": true,
  "created_at": "2026-07-12T12:30:00Z"
}
```

字段说明：

- 访客答卷的 `user` 必须为 `null`。
- `participant_name` 始终有值。
- `is_current` 表示是否为当前登录用户或当前访客 Cookie 对应答卷；URL `answerId` 只能在匹配当前访问者身份时用于定位当前答卷，不得把其他参与者答卷标记为“我的答卷”。
- 并列排名时，分数相同的答卷 `rank` 相同，`is_tied` 为 `true`。

## 5. 前台 API 契约

### 5.1 获取某主页公开测试列表

```text
GET /api/v1/plugins/quiz/users/{owner_id}/tests/
```

权限：允许未登录。

用途：别人访问某主页默契问答页时，获取该主页主人已发布测试列表。

查询参数：

| 参数 | 必填 | 默认 | 说明 |
|------|------|------|------|
| `page` | 否 | 1 | 页码 |
| `page_size` | 否 | 20 | 每页数量 |

响应：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "total": 2,
    "page": 1,
    "page_size": 20,
    "results": []
  }
}
```

规则：

- 只返回 `status=published` 的测试。
- 返回 `QuizTestCard[]`。
- 主页主人不存在时返回 `40004`。

### 5.2 获取我的测试列表

```text
GET /api/v1/plugins/quiz/my/tests/
```

权限：必须登录。

用途：主页主人管理自己的草稿和已发布测试。

查询参数：

| 参数 | 必填 | 默认 | 说明 |
|------|------|------|------|
| `status` | 否 | 空 | `draft` / `published`；为空返回非 deleted 测试 |
| `page` | 否 | 1 | 页码 |
| `page_size` | 否 | 20 | 每页数量 |

响应数据：分页 `QuizTestCard[]`。

规则：

- 不返回 `deleted` 测试。
- 普通用户只能查看自己的测试。

### 5.3 创建测试草稿

```text
POST /api/v1/plugins/quiz/my/tests/
```

权限：必须登录。

请求体：

```json
{
  "title": "你有多了解我？",
  "questions": [
    {
      "question_text": "我最喜欢的颜色是？",
      "order": 1,
      "correct_option_order": 1,
      "source_bank_question_id": 5,
      "options": [
        { "option_text": "蓝色", "order": 1 },
        { "option_text": "红色", "order": 2 }
      ]
    }
  ]
}
```

响应：`QuizTestDetailOwner`，HTTP 201。

规则：

- 创建时状态固定为 `draft`。
- 草稿允许 `questions` 为空或少于 10 道。
- 每个非空题目如有选项，选项数仍必须不超过 4。
- 如果当前用户已有 3 套非 deleted 测试，返回 `40005`。

### 5.4 获取我的测试详情

```text
GET /api/v1/plugins/quiz/my/tests/{test_id}/
```

权限：必须登录且为 owner。

响应：`QuizTestDetailOwner`。

错误：

- 非 owner 返回 `40003`。
- 测试不存在或已 deleted 返回 `40004`。

### 5.5 更新草稿测试

```text
PATCH /api/v1/plugins/quiz/my/tests/{test_id}/
```

权限：必须登录且为 owner。

请求体：同创建草稿。采用整体替换题目列表策略。

规则：

- 仅 `draft` 状态允许更新。
- `published` 状态返回 `40005`，消息为“已发布测试不可编辑”。
- `deleted` 状态返回 `40004`。
- 更新时后端必须整体替换该测试的题目和选项，避免复杂局部 patch 造成顺序不一致。

响应：`QuizTestDetailOwner`。


权限：必须登录且为 owner。

发布校验：

| 校验 | 错误码 | 说明 |
|------|--------|------|
| 测试必须为 draft | 40005 | 已发布或已删除不可发布 |
| 必须正好 10 题 | 40001 | 返回具体缺失信息 |
| 每题必须有 2-4 个选项 | 40001 | 返回题号 |
| 每题必须有标准答案 | 40001 | 返回题号 |
| 标准答案必须属于该题选项 | 40001 | 返回题号 |

响应：`QuizTestDetailOwner`。

发布成功后：

- `status` 变为 `published`。
- 设置 `published_at`。
- 后续不可编辑题目、选项、标准答案。

## 7. 错误码与错误消息

沿用项目错误码。

| 错误码 | HTTP 状态 | 含义 | 示例场景 |
|--------|-----------|------|----------|
| 0 | 200/201 | 成功 | 请求成功 |
| 40001 | 400 | 参数错误 | 题目不足 10 道、选项数量非法、缺少昵称 |
| 40003 | 403 | 无权限 | 非 owner 修改测试、非管理员访问后台 |
| 40004 | 404 | 资源不存在 | 测试不存在、测试未发布、题库题不存在 |
| 40005 | 400 | 操作冲突 | 重复提交、超过 3 套测试、已发布测试不可编辑 |
| 50000 | 500 | 服务器内部错误 | 未捕获异常 |

错误响应示例：

```json
{
  "code": 40005,
  "message": "你已经提交过这套测试",
  "data": {
    "submission_id": 123,
    "leaderboard_url": "/profile/2/plugins/quiz/tests/1/leaderboard?answerId=123"
  }
}
```

发布校验失败时，`data` 必须包含字段级错误，便于前端定位题卡。

示例：

```json
{
  "code": 40001,
  "message": "测试发布校验失败",
  "data": {
    "errors": [
      { "field": "questions", "message": "必须正好 10 道题" },
      { "field": "questions[3].options", "message": "第 4 题至少需要 2 个选项" },
      { "field": "questions[5].correct_option", "message": "第 6 题必须设置标准答案" }
    ]
  }
}
```

## 11. 排名算法契约

答卷榜排名必须按以下算法计算：

1. 过滤 `is_deleted=false` 的答卷。
2. 按 `score_percent DESC, created_at ASC, id ASC` 排序。
3. 相同 `score_percent` 的答卷使用并列排名。
4. 并列后下一个名次跳过已占名次。

示例：

| 排序位置 | 分数 | rank | is_tied |
|----------|------|------|---------|
| 1 | 100 | 1 | false |
| 2 | 90 | 2 | true |
| 3 | 90 | 2 | true |
| 4 | 80 | 4 | false |

通知类型：

```text
plugin_event
```

通知系统实现要求：

- 新增通用通知类型 `plugin_event`，中文含义为“插件动态”。
- 后续插件类通知优先复用 `plugin_event`，不要为每个插件、每个插件动作都新增独立通知类型。
- 具体插件名称、动作含义、展示文案和跳转目标由 `title`、`content`、`link` 承载。
- 现有 `quiz_invite` 是旧版默契问答邀请语义，新版默契问答完成通知不得继续使用 `quiz_invite`。
- 前端通知图标映射必须为 `plugin_event` 使用 `puzzle` 图标。

通知字段：

| 字段 | 规则 |
|------|------|
| recipient | 测试 owner |
| sender | 登录答题用户 |
| title | 必须表达“有人完成了你的默契测试” |
| content | 必须包含参与者昵称和测试标题 |
| link | `/profile/:ownerId/plugins/quiz/tests/:testId/leaderboard?answerId=:submissionId` |

不发送通知的场景：

- 未登录访客提交。
- owner 自己尝试提交自己的测试。
- 重复提交被拒绝。

## 13. 插件摘要契约

主页插件卡片保持入口文案，不展示复杂数据。

`get_profile_card_data(viewer_id, owner_id)` 对 quiz 返回：

```json
{
  "type": "quiz",
  "name": "默契问答",
  "icon": "help-circle",
  "description": "来测测你有多了解我",
  "data": {
    "entry_text": "来测测你有多了解我",
    "published_test_count": 2
  },
  "route": "/profile/2/plugins/quiz"
}
```

显示规则：

- 插件入口始终展示。
- `published_test_count=0` 时仍展示入口。
- 前端卡片主要展示 `entry_text`。
- 不展示平均匹配度、最佳好友、好友排行等旧版数据。

`GET /api/v1/plugins/summary/` 中 quiz 摘要也不得使用旧好友匹配度数据。

## 14. 安全与隐私

### 14.1 标准答案保护

以下接口不得返回标准答案：

- `GET /api/v1/plugins/quiz/users/{owner_id}/tests/`
- `GET /api/v1/plugins/quiz/tests/{test_id}/`
- `POST /api/v1/plugins/quiz/tests/{test_id}/submissions/`
- `GET /api/v1/plugins/quiz/tests/{test_id}/leaderboard/`
- `GET /api/v1/plugins/quiz/my/submissions/`

只有以下接口可以返回标准答案：

- owner 管理接口 `GET /api/v1/plugins/quiz/my/tests/{test_id}/`
- 管理后台测试详情接口 `GET /api/v1/admin/quiz/tests/{test_id}/`
- 管理后台答卷详情接口 `GET /api/v1/admin/quiz/submissions/{submission_id}/`

### 14.2 访客标识保护

- 前台接口不得返回 `visitor_token_hash`。
- 后台列表也不需要返回 `visitor_token_hash`。
- 如后台详情需要排查问题，可只返回脱敏片段，不返回完整哈希。

### 14.3 重复提交保护

- 提交答卷必须使用事务。
- 必须在数据库层建立唯一约束或使用事务锁避免并发重复提交。
- 重复提交返回 `40005`，并附带已有答卷 ID 和答卷榜 URL。

## 15. 测试用例清单

### 15.1 模型与约束

- owner 非 deleted 测试最多 3 套。
- draft 可少于 10 题。
- published 必须正好 10 题。
- published 每题必须 2-4 选项。
- published 每题必须有标准答案。
- published 后不能编辑题目、选项、标准答案。
- deleted 测试不可出现在公开列表。

### 15.2 答题

- 登录用户可以提交他人 published 测试。
- 登录用户不能提交自己的测试。
- 未登录访客必须填写昵称。
- 未登录访客自动获得 `fmh_visitor_id` Cookie。
- 缺少答案、重复题目、非法题目、非法选项均返回 `40001`。
- 同一登录用户重复提交返回 `40005`。
- 同一访客 Cookie 重复提交返回 `40005`。

### 15.3 结果与榜单

- 正确计算 `correct_count`。
- 正确计算 `score_percent`。
- 正确生成固定称号。
- 同分显示并列排名。
- 当前答卷可通过 `answer_id` 高亮。
- 普通前台不返回标准答案。

### 15.4 通知

- 登录用户提交后通知 owner。
- 未登录访客提交后不通知 owner。
- 重复提交不产生通知。
- 通知链接指向答卷榜并携带 `answerId`。

### 15.5 后台

- 管理员可以查看测试详情和标准答案。
- 管理员可以查看答卷详情和逐题答案。
- 管理员删除测试为软删。
- 管理员删除答卷为软删。
- 题库题删除不影响已复制到用户测试中的题目。

## 16. 实施注意事项

- 不要在新接口中继续使用旧版好友匹配度字段。
- 不要让公开答题接口返回标准答案。
- 不要把访客昵称当作唯一身份。
- 不要把 IP 作为防重复主依据。
- 不要在发布后允许修改题目、选项和标准答案。
- 不要把答卷榜做成全站排行榜。
- 不要为结果单独做个人结果页；结果分享统一落到答卷榜。
- 不要物理删除新版业务测试和答卷；业务删除默认软删。
