# 关系匹配插件产品需求文档

> 版本: v1.0  
> 状态: 已收敛待开发  
> 面向读者: 产品、设计、前端、后端、测试  
> 适用范围: FallingMapleHaven 关系匹配插件

---

## 1. 背景与目标

### 1.1 背景

关系匹配插件是一款轻娱乐互动插件。所有用户先完成同一套系统固定的 40 题基础测试生成自己的画像，再通过分享链接或短匹配码与另一位参与者交换画像，系统据此生成两人的关系报告。

### 1.2 目标

| 目标 | 说明 |
|------|------|
| 轻娱乐互动 | 首版定位为轻松、有分享感的关系测试 |
| 双人关系报告 | 用户完成个人画像后，与另一位参与者生成关系结果 |
| 结果可分享 | 结果页可通过链接继续访问，便于分享和回看 |
| 结果可解释 | 结果包含关系类型、双方角色、八维对比和相处建议 |
| 手机优先 | 40 题答题和结果页在移动端可顺畅使用 |

### 1.3 非目标

首版不做以下内容：

| 功能 | 首版处理 |
|------|----------|
| 单人排行榜 | 不做 |
| 逐题对错展示 | 不做 |
| 负面判词 | 不做 |
| 分享图编辑器 | 不做，后续再补 |
| 删除自己的画像或结果 | 不做 |
| 举报入口 | 不做 |
| 历史配对管理 | 不做（只展示历史板块，不做删除、归档、筛选等管理能力） |

## 2. 术语定义

| 术语 | 定义 |
|------|------|
| 基础测试 | 系统固定的一套 40 题测试，用于生成个人画像 |
| 个人画像 | 用户完成测试后得到的八维倾向结果 |
| 参与者 | 参与基础测试并参与关系匹配的人 |
| 访客 | 未登录用户，可填写昵称参与 |
| 私密链接 | 用于访问个人画像状态、邀请他人参与或查看结果的链接 |
| 短匹配码 | 用于交换画像的短数字码 |
| 关系结果 | 两个人画像配对后生成的关系报告 |
| 关系类型 | 关系结果的固定命名，如死党型、青梅竹马型 |

## 3. 角色与权限

### 3.1 角色

| 角色 | 能力 |
|------|------|
| 登录用户 | 完成测试、查看个人状态、生成和查看关系结果、查看历史 |
| 未登录访客 | 填昵称参与测试、生成个人画像、通过私密链接参与匹配、查看结果 |
| 管理员 | 查看画像、匹配结果、逐题答案和统计数据 |

### 3.2 首版权限规则

| 场景 | 权限 |
|------|------|
| 进入插件主页 | 登录用户与访客均可 |
| 开始基础测试 | 登录用户与访客均可 |
| 未登录首屏 | 可选择继续作为访客、登录、注册 |
| 查看个人画像状态 | 登录用户可完整查看；访客通过私密链接回看 |
| 生成关系结果 | 只要双方画像都存在即可生成 |
| 查看关系结果 | 持有结果链接即可查看完整报告 |
| 查看后台数据 | 仅管理员 |

## 4. 核心玩法

### 4.1 玩法概述

1. 用户先完成一套固定 40 题基础测试。
2. 系统生成个人画像，但首版不单独开放完整单人画像页。
3. 用户复制个人画像分享链接或短匹配码，发给另一位参与者。
4. 对方打开链接后，如果还没做测试，先填写昵称并完成测试；如果已经有画像，系统直接进入匹配流程。
5. 两份画像配对后，系统生成唯一关系结果。
6. 结果页展示双方名字、关系类型、副标题、八维雷达图、双向对比、双方摘要、相处亮点和建议。

### 4.2 结果原则

| 规则项 | 首版规则 |
|--------|----------|
| 画像生成 | 每个人只需要做一次基础测试，首版固定使用同一份画像 |
| 关系结果 | 同一对画像只生成一次关系结果 |
| 关系类型 | 固定类型优先 |
| 结果访问 | 默认走私密链接访问 |
| 分享范围 | 持有结果链接的人可查看完整报告 |
| 重测 | 首版不开放 UI，但接口和文档保留 |

## 5. 关系类型

首版关系类型库以现实+诗意为主，避免负面判词，允许少量亲密表达弱化出现。

### 5.1 首版固定类型

| 类型 |
|------|
| 死党型 |
| 兄弟/姐妹型 |
| 青梅竹马型 |
| 知己型 |
| 师生型 |
| 双胞胎型 |
| 欢喜冤家型 |
| 陪伴型 |
| 互补型 |
| 镜像型 |
| 反差型 |
| 治愈型 |
| 成长型 |
| 冒险型 |
| 港湾型 |
| 亲子型 |

### 5.2 命名规则

| 规则 | 说明 |
|------|------|
| 结果名称 | 使用“类型名 + 副标题”格式 |
| 副标题 | 用一句更诗意、更温暖的话补充解释 |
| 语气 | 现实+诗意 |
| 恋爱感 | 仅在少数类型中弱化出现，不作为主表达 |

## 6. 页面与板块

### 6.1 个人主页插件入口

位置：个人主页插件区。  
首版文案：`看看你们像什么`

### 6.2 插件主页

插件主页包含以下板块：

| 板块 | 说明 |
|------|------|
| 我的画像状态 | 显示是否已完成基础测试，以及可用的分享入口 |
| 开始测试 | 进入 40 题基础测试 |
| 输入匹配码 | 用短数字码进入匹配 |
| 匹配历史 | 登录用户可查看自己和配对过的其他人的关系报告，点击直接进入结果页 |
| 使用说明 | 说明先完成测试，再交换链接或匹配码生成关系结果 |
| 分享链接 | 别人点进来后会进入插件主页并携带分享信息，可直接参与答题，并自动和分享人匹配 |

### 6.3 测试答题页

| 规则 | 说明 |
|------|------|
| 题量 | 40 题 |
| 题型 | 可混合量表、二选一、多选等形式，按题目设计决定 |
| 页面形式 | 逐题翻页 |
| 进度展示 | 只显示总进度，不显示维度名 |
| 移动端 | 优先保证顺畅答题 |

### 6.4 邀请中页

当用户已完成自己的画像，但对方尚未完成时，页面显示“邀请中”状态，并提供继续邀请、复制链接、输入匹配码等入口。

### 6.5 关系结果页

结果页首屏顺序：

1. 双方名字
2. 关系类型 + 副标题
3. 八维雷达图
4. 八维双向对比
5. 双方摘要
6. 相处亮点
7. 相处建议

结果页需要同时适配移动端和桌面端，桌面端逻辑与移动端一致。

## 7. 用户流程

### 7.1 登录用户第一次使用

1. 从个人主页进入插件主页。
2. 选择开始测试。
3. 完成 40 题。
4. 系统生成画像。
5. 回到插件主页，看到分享链接和短码。
6. 将链接或短码发给另一位参与者。
7. 双方完成后生成关系结果。
8. 进入结果页查看完整报告。

### 7.2 登录用户打开别人的分享链接

| 情况 | 流程 |
|------|------|
| 自己还没测试 | 先填身份，再答题，完成后自动匹配 |
| 自己已有画像但未匹配 | 自动匹配 |
| 已经匹配过 | 直接进入结果页 |

### 7.3 未登录访客使用

未登录首屏提供三种路径：

1. 继续作为访客
2. 登录
3. 注册

如果选择继续作为访客：

1. 填写昵称。
2. 完成 40 题测试。
3. 生成个人画像。
4. 通过私密链接或短匹配码继续参与匹配。
5. 进入结果页查看完整报告。

### 7.4 自己打开自己的分享链接

打开自己的分享链接时，优先回到插件主页，而不是进入结果页。

## 8. 测试与画像

### 8.1 测试规则

| 规则 | 说明 |
|------|------|
| 总题数 | 40 题 |
| 题目形式 | 情景题、量表题、二选一、多选题均可 |
| 计分方式 | 多维权重 |
| 维度覆盖 | 按场景覆盖八维 |
| 维度展示 | 答题过程中不展示八维名称 |

### 8.2 八维定义

| 维度 | 说明 |
|------|------|
| 主导 | 关系里的推动、决策、引导倾向 |
| 照顾 | 安抚、照料、承担感 |
| 依赖 | 需要陪伴、需要回应的倾向 |
| 共情 | 理解对方情绪、换位思考的倾向 |
| 浪漫 | 仪式感、亲密表达、情感氛围倾向 |
| 玩乐 | 幽默、轻松、一起找乐子的倾向 |
| 稳定 | 持续性、踏实感、可依赖程度 |
| 成熟 | 沟通能力、边界感、处理问题能力 |

### 8.3 分数规则

| 项 | 规则 |
|----|------|
| 分数范围 | 1-10 |
| 含义 | 都是倾向强度，不是好坏评价 |
| 展示方式 | 结果页展示八维雷达图和双向对比 |

### 8.4 用户摘要

个人画像不单独做完整详情页，但在结果页中展示双方摘要。摘要形式为短段落。

---

## 9. 结果规则

### 9.1 结果内容

关系结果页必须包含：

| 模块 | 说明 |
|------|------|
| 关系类型 | 固定类型优先，使用“类型名 + 副标题” |
| 双方角色 | 说明两个人在这段关系里的角色 |
| 八维雷达图 | 展示双方八维对比 |
| 八维双向对比 | 逐维解释两人哪里像、哪里互补 |
| 双方摘要 | 每人一段短摘要 |
| 相处亮点 | 展示这段关系的正向特征 |
| 相处建议 | 给出温暖、正向的相处建议 |

### 9.2 命名与表达

| 规则 | 说明 |
|------|------|
| 排版 | 结果页首屏先展示双方名字，再展示关系类型 |
| 语气 | 全程温暖正向 |
| 负面表达 | 不做负面判词，只讲互补和相处方式 |
| 恋爱感 | 仅在少数类型中弱化出现 |

### 9.3 历史与重复

| 规则 | 说明 |
|------|------|
| 历史配对 | 插件主页固定展示历史板块，点进历史项直接进入对应结果页 |
| 同一对结果 | 一对画像只生成一次关系结果 |
| 再次打开 | 若已生成结果，直接进入结果页 |

## 10. 分享与通知

### 10.1 分享方式

首版支持：

| 方式 | 说明 |
|------|------|
| 结果链接 | 可直接打开完整报告 |
| 画像链接 | 继续邀请他人参与匹配 |
| 短匹配码 | 用于交换画像 |

首版不做分享图，后续再补。

### 10.2 私密访问

| 规则 | 说明 |
|------|------|
| 访客 | 需要昵称 |
| 访问结果 | 通过私密链接访问 |
| 第三方 | 拿到结果链接后可看完整报告 |
| 回看 | 访客通过链接回看，登录用户通过历史查看 |

### 10.3 通知

| 场景 | 规则 |
|------|------|
| 登录用户完成匹配 | 双方都通知 |
| 访客完成匹配 | 记录结果，不做通知 |

通知类型沿用通用 `plugin_event`。

## 11. 管理后台需求

首版后台以查看和统计为主，不做题库编辑。

### 11.1 后台能力

| 能力 | 说明 |
|------|------|
| 查看画像 | 查看用户或访客画像 |
| 查看匹配 | 查看两人关系结果 |
| 查看答案 | 查看逐题答案 |
| 统计数据 | 查看完成测试数、匹配数、访客数等 |

### 11.2 题库策略

| 项 | 首版处理 |
|----|----------|
| 题目 | 固定 |
| 选项 | 固定 |
| 权重 | 固定 |
| 后台编辑 | 不开放 |

| 规则 | 说明 |
|------|------|

## 13. 数据设计建议

本节为产品层建议，具体字段由技术实现时结合现有项目约定确定。

### 13.1 基础画像

| 字段 | 说明 |
|------|------|
| owner | 画像拥有者 |
| title | 画像名称或测试名称 |
| status | 已完成 / 邀请中 / 已匹配 |
| created_at | 创建时间 |
| updated_at | 更新时间 |

### 13.2 关系结果

| 字段 | 说明 |
|------|------|
| participant_a | 第一位参与者 |
| participant_b | 第二位参与者 |
| relation_type | 固定关系类型 |
| subtitle | 副标题 |
| summary_a | A 的短摘要 |
| summary_b | B 的短摘要 |
| dimension_scores | 八维分数 |
| created_at | 生成时间 |

### 13.3 结果唯一性

| 规则 | 说明 |
|------|------|
| 用户对唯一 | 同一用户和同一对象只生成一份关系结果 |
| 历史保留 | 首版长期保留 |

## 14. 验收标准

### 14.1 主链路

必须优先完成：

```text
进入插件主页 → 完成基础测试 → 生成个人画像 → 复制链接或短码 → 对方参与 → 生成关系结果 → 查看完整报告
```

### 14.2 验收项

| 编号 | 验收项 |
|------|--------|
| A1 | 登录用户可以从个人主页进入插件主页 |
| A2 | 未登录用户可以进入插件主页并选择访客、登录或注册 |
| A3 | 用户可以完成 40 题基础测试 |
| A4 | 系统可以生成个人画像 |
| A5 | 用户可以通过链接或短码邀请另一位参与者 |
| A6 | 对方若未做测试，可以先填昵称再答题 |
| A7 | 对方若已有画像，可以直接进入匹配 |
| A8 | 同一对画像只生成一份关系结果 |
| A9 | 结果页展示双方名字、关系类型、副标题、八维图和文字分析 |
| A10 | 结果页默认可通过结果链接完整访问 |
| A11 | 登录用户完成匹配后双方都能收到通知 |
| A12 | 管理员可查看画像、匹配、答案和统计数据 |
