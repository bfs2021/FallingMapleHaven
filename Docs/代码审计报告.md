### 🔴 BUG 1 — 加入申请列表无法显示申请人信息

## 八、群组功能二次审查（2026-07-01 补充）

*审查范围：迭代 D/E 全部改动 + 迭代 A/B/C 回归检查。基于 `Docs/09-群组功能需求补充规格.md` §3.2 权限矩阵逐项对照。*

### 🔴 BUG 3 — `GroupUpdateView` 权限过宽（新增）

**文件**: `backend/apps/groups/views.py:92`  
**描述**: 检查条件为 `membership.role != "admin"`，允许任何管理员编辑小组信息。PRD §3.2 规定仅组长可编辑。  
**修复方向**: 改为 `request.user != group.creator`。

### 🔴 BUG 4 — `GroupMemberManageView` 权限过宽（新增）

**文件**: `backend/apps/groups/views.py:176`  
**描述**: 同样使用 `membership.role != "admin"`，导致管理员可以：
- 任意 **设为管理员**（应仅组长可操作）
- 任意 **取消管理员**（应仅组长可操作）
- **移除其他管理员**（管理员应只能移除普通成员）

PRD §3.2 权限矩阵对照：

| 操作 | 组长 | 管理员 |
|------|:----:|:------:|
| 移除成员 | ✅ | ✅（不可移除组长/其他管理员）|
| 设为管理员 | ✅ | ❌ |
| 取消管理员 | ✅ | ❌ |

**修复方向**: 拆分 action 权限——`promote_admin`/`demote_admin` 要求 `request.user == group.creator`；`remove` 中管理员仅允许 `target.role == "member"`。

### 🟡 BUG 5 — `GroupDeleteView` 缺少事务（新增）

**文件**: `backend/apps/groups/views.py:245-263`  
**描述**: 4 步写操作（删成员→删聊天室→置空Post→删Group）无 `transaction.atomic()`，中途失败导致数据不一致。  
**修复方向**: 包裹 `with transaction.atomic():`。

### 🟡 BUG 6 — `GroupTransferView` 缺少事务（新增）

**文件**: `backend/apps/groups/views.py:269-301`  
**描述**: 3 次 `save()`（降旧组长、升新组长、改 creator）无 `transaction.atomic()`，中途失败导致角色/所有权不一致。  
**修复方向**: 包裹 `with transaction.atomic():`。

### 🟡 BUG 7 — 公开组直接加入未发 `group_member_joined` 通知（新增）

**文件**: `backend/apps/groups/views.py:132-138`  
**描述**: 公开组直接加入路径缺少 `group_member_joined` 通知。PRD §7.1 规定新成员加入应通知全体成员。私密组审批通过路径已正确发送（`GroupJoinRequestHandleView:367-376`），但公开组路径遗漏。  
**修复方向**: 在 `GroupMember.objects.create(...)` 后添加与 `GroupJoinRequestHandleView` 相同的通知逻辑。

### 🟢 PERF 1 — `GroupPostsView` N+1 查询（新增）

**文件**: `backend/apps/groups/views.py:224`  
**描述**: `Post.objects.filter(group_id=pk)` 未加 `.select_related("group")`，`PostSerializer.get_group()` 对每篇帖子单独查 group。  
**修复方向**: 加 `.select_related("group")`。

### 🟢 PERF 2 — `GroupDetailView` 缺少 chat_room 预取（新增）

**文件**: `backend/apps/groups/views.py:69-71`  
**描述**: `get_chat_room_id` 每次详情请求多一次手动查询，未纳入 `prefetch_related`。  
**修复方向**: `prefetch_related` 中添加 `Prefetch('chat_rooms', queryset=ChatRoom.objects.filter(group=...))` 或简化。

## 九、群组功能三次审查（2026-07-01 回归测试）

*审查范围：BUG 1-7 修复验证 + 全量 API 回归。*

### 🔴 回归缺陷 1 — 迁移 `0004` 未 apply 导致广场/点赞/评论/删除全部 500

**根因**: `makemigrations` 创建了迁移文件但未执行 `migrate`，`feed_post` 表缺少 `sync_to_profile` 列，所有读 Post 表的查询抛出 `OperationalError: no such column: feed_post.sync_to_profile`。

**影响范围**: 广场列表、点赞、评论、删除、详情等所有涉及 Post 的接口。

**修复**: 执行 `python manage.py migrate feed`。已在修复验证中确认 API 恢复正常。

### 🔴 回归缺陷 2 — `GroupListView` 双 JOIN 导致 COUNT 膨胀

**根因**: `.annotate(Count('members'))` 和 `.filter(members__user=request.user)` 先后对 `groups_groupmember` 做两次 JOIN，COUNT 在双 JOIN 的结果集上计算，仅**认证成员**看到的人数膨胀（2→4）。

**修复**: 将 `.filter(members__user=request.user)` 改为 `.filter(id__in=子查询)`，消除多余 JOIN。已在三种用户场景（成员/匿名/非成员认证）验证 COUNT 正确。

### 🟡 回归缺陷 3 — `transaction` 未导入导致转让/解散 500

**根因**: `groups/views.py` 中添加了 `with transaction.atomic()` 但缺少 `from django.db import transaction`，运行时 `NameError`。前端静默捕获，用户无反馈。

**修复**: 添加 `from django.db import transaction`。已在 API 测试中确认转让返回 200。

### 🟢 回归缺陷 4 — 群组内帖子点赞/删除 UI 不刷新

**根因**: `PostActions.vue`/`PostCard.vue` 调用 `feedStore.toggleLike/deletePost`，仅更新 `feedStore.posts`。`GroupDetailPage.vue` 使用本地 `posts` ref，UI 不更新。

**修复**: `PostActions` 新增 `like-updated` 事件、`PostCard` 新增 `deleted` 事件、`GroupDetailPage` 监听后更新本地 `posts`。
