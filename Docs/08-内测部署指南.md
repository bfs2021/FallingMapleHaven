# 内测部署指南

让朋友从外网连上你电脑上运行的枫落港，进行内测体验。

---

## 前提

- 本机已能正常启动项目（后端 + 前端）
- 朋友端只需浏览器，无需安装任何软件
- 项目所在 Windows 电脑在内测期间保持开机、不断网

---

## 方案对比

| 方案 | 朋友是否需装软件 | 速度 | 稳定性 | 适合场景 |
|------|------------------|------|--------|----------|
| **ngrok** | 否 | 中 | 中 | 快速分享，临时体验 |
| **Tailscale** | 是（装 Tailscale） | 好 | 好 | 多人长期内测 |
| **frp** | 否 | 好 | 好 | 有公网服务器时的最佳方案 |

如果只是快速验证功能是否正常，先用 ngrok。如果需要多人、长时间稳定内测，用 Tailscale 或 frp。

---

## 方案一：ngrok（快速体验）

ngrok 将你本地的端口暴露到一个公网 URL，朋友通过该 URL 直接访问。

### 1. 注册并安装 ngrok

1. 打开 https://ngrok.com 注册账号（免费）
2. 下载 Windows 版 https://ngrok.com/download
3. 解压得到一个 `ngrok.exe`，把它放到一个固定位置（如 `D:\ngrok\ngrok.exe`）
4. 打开命令行执行认证（Token 在 ngrok Dashboard 的 Your Authtoken 处）：

```bash
D:\ngrok\ngrok.exe config add-authtoken <你的Token>
```

### 2. 启动项目

```bash
# 终端 1 - 启动后端
cd backend
.venv\Scripts\activate
python manage.py runserver

# 终端 2 - 启动前端
cd frontend
npm run dev
```

确认本机能通过 `http://localhost:5173` 正常访问。

### 3. 暴露前端端口

```bash
# 终端 3 - 启动 ngrok
D:\ngrok\ngrok.exe http http://localhost:5173
```

看到如下输出表示成功：

```
Forwarding  https://xxxx.ngrok-free.app -> http://localhost:5173
```

### 4. 配置后端允许 ngrok 域名

ngrok 使用的是 HTTPS，Django 默认只信任 localhost 来源，需要手动添加。编辑 `backend/config/settings/dev.py`：

```python
ALLOWED_HOSTS = ["localhost", "127.0.0.1", "https://xxxx.ngrok-free.app"]  # ← 替换为你的实际 ngrok 地址
```

此外，`backend/config/settings/base.py` 中已有 `CORS_ALLOWED_ORIGINS` 和 `CSRF_TRUSTED_ORIGINS`，按需追加：

```python
# base.py — 仅当缺失时添加
CORS_ALLOWED_ORIGINS = [
    "http://localhost:5173",
    "https://xxxx.ngrok-free.app",  # ← 替换为你的实际 ngrok 地址
]

CSRF_TRUSTED_ORIGINS = [
    "http://localhost:5173",
    "http://127.0.0.1:5173",
    "https://xxxx.ngrok-free.app",  # ← 替换为你的实际 ngrok 地址
]
```

> **注意：** `ALLOWED_HOSTS` 影响 WebSocket Origin 校验（`chat/consumers.py`），漏配会导致聊天 WebSocket 连接被反复拒绝（日志中重复出现 `WebSocket REJECT /ws/chat/`）。
> 每次 ngrok 重启 URL 会变化（免费版），需同步修改这 3 处域名。

### 5. 分享给朋友

将 `https://xxxx.ngrok-free.app` 复制给朋友即可。

### 注意事项

- **免费版限制**：ngrok 免费版每分钟 60 请求、每月 40GB 流量，内测够用。URL 每次重启会变化（付费版可固定）。
- **WebSocket 支持**：ngrok 自动支持 WebSocket，但需后端 `ALLOWED_HOSTS` 包含 ngrok 域名，否则 WebSocket 连接会被拒（见第 4 步）。
- **媒体文件**：朋友上传的图片/文件会保存在本机 `backend/media/` 下；ngrok 免费版对传输速度有限制，大文件上传可能较慢。

## 方案二：Tailscale（适合多人长期内测）

Tailscale 基于 WireGuard 组建虚拟局域网，所有设备就像在同一个局域网内互通，速度接近直连。

### 1. 注册并安装 Tailscale

1. 打开 https://tailscale.com 注册账号（免费版支持最多 3 人，内测够用。如需更多人可用 GitHub Education Pack 或自建 Headscale）
2. **你的电脑** 和 **每个朋友的电脑** 都下载安装 Tailscale：
   - Windows / macOS / Linux / 手机：https://tailscale.com/download
3. 所有人在各自设备上登录同一个 Tailscale 账号（或你邀请他们加入你的网络）

### 2. 确认 Tailscale IP

安装登录后，在命令行运行：

```bash
ipconfig
```

找到 Tailscale 虚拟网卡的 IPv4 地址，通常是 `100.x.x.x` 格式。记下这个 IP。

或者直接看系统托盘 Tailscale 图标 -> 右键 -> 显示 IP 地址。

### 3. 修改前端配置（重要）

因为 Vue 开发服务器有代理转发，朋友访问时需要通过真实的局域网 IP 直连后端，不能走 Vite 代理。有两种做法：

#### 方式 A：构建前端 + 用 Django 直接托管（推荐）

构建前端静态文件，让 Django 一并托管：

```bash
cd frontend
npm run build
```

编辑 `backend/config/settings/base.py`，追加：

```python
ALLOWED_HOSTS = ['localhost', '127.0.0.1', '100.x.x.x']  # 替换为你的 Tailscale IP

CSRF_TRUSTED_ORIGINS = [
    "http://localhost:5173",
    "http://127.0.0.1:5173",
    "http://100.x.x.x:8000",          # 替换
]

CORS_ALLOWED_ORIGINS = [
    'http://localhost:5173',
    'http://100.x.x.x:8000',          # 替换
]
```

然后启动后端（不再需要前端 dev server）：

```bash
cd backend
python manage.py runserver 0.0.0.0:8000
```

告诉朋友访问 `http://100.x.x.x:8000`（你的 Tailscale IP + 端口 8000）。

> 注意：这种方式下前端路由是 Django 直接托管，路由需要确认 Django 配置了前端入口。如果 `dev.py` 中没有托管前端静态文件的配置，可以改为下面的方式 B。

#### 方式 B：分别暴露前后端（保留 dev server）

前后端分别绑到 `0.0.0.0`，朋友分别访问前端端口（WebSocket 和 API 请求会由前端 dev server 代理）。

```bash
# 终端 1 - 后端监听所有网卡
cd backend
python manage.py runserver 0.0.0.0:8000

# 终端 2 - 前端也监听所有网卡
cd frontend
npm run dev -- --host 0.0.0.0
```

朋友通过 `http://<你的 Tailscale IP>:5173` 访问。

### 4. 分享给朋友

把 `http://100.x.x.x:5173`（或 `http://100.x.x.x:8000`）发给朋友即可。

## 方案三：frp（有公网服务器时最佳）

frp 利用一台有公网 IP 的服务器做中转，把本机端口映射到服务器的某个端口，朋友直接访问服务器地址即可。

### 1. 在服务端部署 frps

登录你的公网服务器（Linux），下载并配置 frps：

```bash
# 下载 frp（以 v0.61.0 为例，去 https://github.com/fatedier/frp/releases 查最新版）
wget https://github.com/fatedier/frp/releases/download/v0.61.0/frp_0.61.0_linux_amd64.tar.gz
tar -xzf frp_0.61.0_linux_amd64.tar.gz
cd frp_0.61.0_linux_amd64
```

编辑 `frps.toml`：

```toml
bindPort = 7000                # frp 控制端口
vhostHTTPPort = 8080           # HTTP 监听端口（朋友访问的端口）
```

启动服务端：

```bash
./frps -c frps.toml
```

> 建议用 `systemd` 或 `screen` / `tmux` 保持后台运行。

如果服务器有防火墙（如阿里云/腾讯云安全组），需放行 `7000` 和 `8080` 端口。

### 2. 在本机部署 frpc

下载 Windows 版 frp（同上链接，选 `windows_amd64` 版本）。解压后编辑 `frpc.toml`：

#### 有域名的情况

如果你有域名（如 `example.com`）解析到了服务器，用 HTTP 代理：

```toml
serverAddr = "<你的服务器公网IP>"
serverPort = 7000

[[proxies]]
name = "枫落港前端"
type = "http"
localIP = "127.0.0.1"
localPort = 5173
customDomains = ["example.com"]

[[proxies]]
name = "枫落港后端"
type = "http"
localIP = "127.0.0.1"
localPort = 8000
customDomains = ["example.com"]
```

朋友访问 `http://example.com:8080` 即可。

#### 无域名的情况

没有域名时，HTTP 代理因缺少 `Host` 头路由会失效，改用 TCP 代理：

```toml
serverAddr = "<你的服务器公网IP>"
serverPort = 7000

# 将本机 5173 端口映射到服务器的 8080 端口（TCP 模式）
[[proxies]]
name = "枫落港前端"
type = "tcp"
localIP = "127.0.0.1"
localPort = 5173
remotePort = 8080

# 将本机 8000 端口映射到服务器的 8000 端口
[[proxies]]
name = "枫落港后端"
type = "tcp"
localIP = "127.0.0.1"
localPort = 8000
remotePort = 8000
```

朋友访问 `http://<服务器IP>:8080` 即可。TCP 模式无 `Host` 头限制，且自动支持 WebSocket。

### 3. 配置后端允许外部访问

编辑 `backend/config/settings/base.py`：

```python
ALLOWED_HOSTS = [
    'localhost',
    '127.0.0.1',
    '<你的服务器公网IP>',
    'example.com',           # 如果有域名
]

CSRF_TRUSTED_ORIGINS = [
    "http://localhost:5173",
    "http://127.0.0.1:5173",
    "http://<你的服务器公网IP>:8080",
    "http://example.com:8080",       # 如果有域名
]

CORS_ALLOWED_ORIGINS = [
    'http://localhost:5173',
    'http://<你的服务器公网IP>:8080',
    'http://example.com:8080',
]

CHANNEL_ALLOWED_ORIGINS = [
    'http://localhost:5173',
    'http://<你的服务器公网IP>:8080',
    'http://example.com:8080',
]
```

### 4. 启动

```bash
# 本机 - 终端 1 后端
cd backend && .venv\Scripts\activate && python manage.py runserver

# 本机 - 终端 2 前端
cd frontend && npm run dev

# 本机 - 终端 3 frpc
cd frp_0.61.0_windows_amd64 && ./frpc.exe -c frpc.toml

# 服务端保持 frps 运行
```

### frp 的优势

- **固定地址**：只要服务器 IP 不变、frp 不停，地址永远不变
- **速度可控**：取决于你的服务器带宽，远好于 ngrok 免费版限速
- **WebSocket 原生支持**：TCP 模式下无任何额外限制
- **无第三方依赖**：只用你自己的服务器

## 常见问题

### Q：朋友访问时看不到图片 / 图片裂了

确保后端 `ALLOWED_HOSTS` 包含了 ngrok 域名/Tailscale IP/服务器 IP，且 `MEDIA_URL` 使用相对路径。Vite 代理会处理 `/media` 转发，一般不需要额外配置。

### Q：WebSocket 连不上，聊天功能不可用

- ngrok：免费版支持 WebSocket，确认没有达到速率限制
- Tailscale：确保朋友能 ping 通你的 Tailscale IP，检查防火墙是否放行了 Tailscale
- frp：TCP 模式自动支持，HTTP 模式也兼容 WebSocket
- 后端 `CHANNEL_ALLOWED_ORIGINS` 需要包含朋友访问的地址

### Q：如何让朋友体验匿名提问箱 / 默契问答？

所有功能都已包含在前端路由中。朋友登录后即可在个人主页看到插件入口。

### Q：内测结束后如何清理？

- ngrok：关闭终端窗口即可
- Tailscale：在设置中禁用或退出账号，或直接卸载
- frp：关闭 frpc 和 frps 进程即可
- 数据库测试数据：如有需要可清空数据库重新迁移

## 快速启动脚本（内测用）

创建 `start-test.bat` 放在项目根目录，一键启动后端 + 前端：

```batch
@echo off
cd /d "%~dp0"

echo 启动后端...
start "Django" cmd /c "cd backend && .venv\Scripts\activate && python manage.py runserver"

echo 启动前端...
start "Vite" cmd /c "cd frontend && npm run dev"

echo 全部启动完成！
pause
```

如果使用 ngrok，额外添加：

```batch
timeout /t 5

echo 启动 ngrok...
start "ngrok" cmd /c "D:\ngrok\ngrok.exe http http://localhost:5173"
```
