# 关系匹配插件技术契约

> 版本: v1.0  
> 状态: 已收敛待开发  
> 前置产品文档: `Docs/16-关系匹配插件产品需求文档.md`  
> 面向读者: 前端、后端、测试、代码审查  
> 目标: 固定关系匹配插件的数据模型、接口、枚举、权限、错误码、前端路由、通知和算法契约，使后续开发可以严格按本文实现。

---

## 1. 总体约定

### 1.1 插件标识

关系匹配插件在代码和接口中的统一标识必须使用：

```text
relation_match
```

约定：

- `plugin_type` 必须使用 `relation_match`。
- 前端插件注册 `type` 必须使用 `relation_match`。
- 后端接口路径必须挂在 `/api/v1/plugins/relation-match/` 下。
- 后台接口必须挂在 `/api/v1/admin/relation-match/` 下。

### 1.2 新旧版本关系

新版关系匹配插件不兼容旧插件语义，也不沿用默契问答、匿名提问箱的业务含义。

### 1.3 API 基础规范

所有新版接口基础路径：

```text
/api/v1/plugins/relation-match/
```

所有后台接口基础路径：

```text
/api/v1/admin/relation-match/
```

统一响应格式：

```json
{
  "code": 0,
  "message": "success",
  "data": {}
}
```

分页响应格式：

```json
{
  "total": 100,
  "page": 1,
  "page_size": 20,
  "results": []
}
```

### 1.4 认证规范

| 场景 | 认证要求 |
|------|----------|
| 插件主页 | 允许未登录 |
| 基础测试答题 | 允许未登录 |
| 私密链接访问结果 | 允许未登录 |
| 生成画像 | 允许未登录 |
| 我的画像页（`my/`） | 允许未登录 |
| 分享落地页（`shares/{share_code}/`） | 允许未登录 |
| 查看我的历史（`my/pairs/`） | 允许未登录（访客凭 Cookie 识别） |
| 管理后台 | 必须登录且为管理员 |

### 1.5 链接授权

结果页对第三方的完整报告访问规则：**拿到结果链接即可无登录查看完整报告**。

### 1.6 访客与 Cookie

| 项 | 约定 |
|----|------|
| Cookie 名称 | `fmh_relation_visitor_id` |
| 有效期 | 1 年 |
| 用途 | 未登录访客同浏览器身份识别、防重复测试、防重复匹配 |
| 生成方 | 后端 |
| 存储要求 | 数据库中不得保存 Cookie 明文，只保存哈希 |
| 前端使用 | 前端不需要手动读写该 Cookie |

访客还需要填写昵称，用于展示和结果页摘要。访客首版不使用口令作为核心校验项。

### 1.7 通知类型

关系匹配插件完成后的通知必须复用通用通知类型：

```text
plugin_event
```

不得新增独立通知类型。

## 2. 枚举与常量

### 2.1 测试状态 `RelationMatchTestStatus`

| 值 | 含义 | 前台可见 | 可提交 | 可编辑题目 |
|----|------|----------|--------|------------|
| `draft` | 草稿 | 否 | 否 | 是 |
| `published` | 已发布 | 是 | 是 | 否 |
| `deleted` | 已删除 | 否 | 否 | 否 |

### 2.2 参与者类型 `RelationMatchParticipantType`

| 值 | 含义 |
|----|------|
| `user` | 登录用户 |
| `visitor` | 未登录访客 |

### 2.3 题型 `RelationMatchQuestionType`

首版支持：

| 值 | 含义 |
|----|------|
| `single_choice` | 单选题 |
| `scale` | 量表题 |
| `multi_select` | 多选题 |
| `either_or` | 二选一题 |

### 2.4 核心常量

| 常量 | 值 |
|------|----|
| `BASE_QUESTION_COUNT` | 40 |
| `MIN_OPTIONS_PER_QUESTION` | 2 |
| `MAX_OPTIONS_PER_QUESTION` | 4 |
| `DIMENSION_COUNT` | 8 |
| `DIMENSION_MIN_SCORE` | 1 |
| `DIMENSION_MAX_SCORE` | 10 |
| `MAX_IMAGES_PER_USER` | 1 |
| `MAX_RELATION_RESULTS_PER_PAIR` | 1 |

### 2.5 测试归属

基础测试是**全局固定测试**，不属于任何 owner。

约束：

- 系统只维护一份基础测试。
- 前台和后台都不得将基础测试理解为某个用户自己的私有测试。
- 用户完成的是同一套固定题，不存在“创建测试”流程。

### 2.5 维度标识

八维维度必须使用以下固定标识：

| 标识 | 中文 |
|------|------|
| `dominance` | 主导 |
| `care` | 照顾 |
| `dependence` | 依赖 |
| `empathy` | 共情 |
| `romance` | 浪漫 |
| `playfulness` | 玩乐 |
| `stability` | 稳定 |
| `maturity` | 成熟 |

### 2.6 关系类型标识

首版固定关系类型标识必须至少覆盖以下类型：

| 标识 | 中文名 |
|------|--------|
| `bestie` | 死党型 |
| `siblings` | 兄弟/姐妹型 |
| `childhood_friend` | 青梅竹马型 |
| `confidant` | 知己型 |
| `teacher_student` | 师生型 |
| `twin` | 双胞胎型 |
| `frienemy` | 欢喜冤家型 |
| `companion` | 陪伴型 |
| `complementary` | 互补型 |
| `mirror` | 镜像型 |
| `contrast` | 反差型 |
| `healing` | 治愈型 |
| `growing` | 成长型 |
| `adventure` | 冒险型 |
| `harbor` | 港湾型 |
| `parent_child` | 亲子型 |

关系类型数量首版可后续微调，但上述标识一旦写入实现不得随意改名。

## 3. 数据模型契约

本节定义逻辑模型和字段契约。Django 实现可以添加索引、时间字段、软删字段等，但不能改变对外字段语义。

### 3.1 `RelationMatchTest`

约定表名：

```text
plugins_relationmatchtest
```

字段：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | BigAutoField | 是 | 测试 ID |
| `slug` | CharField(50, unique=True) | 是 | 固定测试标识，首版建议 `current` |
| `title` | CharField(50) | 是 | 测试标题 |
| `status` | CharField | 是 | `draft` / `published` / `deleted` |
| `created_at` | DateTime | 是 | 创建时间 |
| `updated_at` | DateTime | 是 | 更新时间 |
| `published_at` | DateTime(null=True) | 否 | 发布时间 |
| `deleted_at` | DateTime(null=True) | 否 | 删除时间 |

约束：

- 全局仅允许一套 `status != deleted` 的基础测试。
- 测试发布后不可修改题目、选项、维度权重。
- `deleted` 状态前台不可见、不可提交。
- `slug` 必须固定指向当前测试，首版不做多套测试切换。

### 3.2 `RelationMatchQuestion`

约定表名：

```text
plugins_relationmatchquestion
```

字段：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | BigAutoField | 是 | 题目 ID |
| `test` | FK(RelationMatchTest) | 是 | 所属测试 |
| `question_type` | CharField | 是 | `single_choice` / `scale` / `multi_select` / `either_or` |
| `question_text` | CharField(120) | 是 | 题目文案 |
| `scene_tag` | CharField(50) | 否 | 场景标签 |
| `order` | PositiveIntegerField | 是 | 题目顺序，从 1 开始 |
| `created_at` | DateTime | 是 | 创建时间 |
| `updated_at` | DateTime | 是 | 更新时间 |

约束：

- 同一测试内 `order` 唯一。
- 首版基础测试必须正好 40 题。

### 3.3 `RelationMatchQuestionOption`

约定表名：

```text
plugins_relationmatchquestionoption
```

字段：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | BigAutoField | 是 | 选项 ID |
| `question` | FK(RelationMatchQuestion) | 是 | 所属题目 |
| `option_text` | CharField(60) | 是 | 选项文案 |
| `order` | PositiveIntegerField | 是 | 选项顺序，从 1 开始 |

约束：

- 同一题目内 `order` 唯一。
- 每题必须 2-4 个选项。

### 3.4 `RelationMatchTestAnswer`

约定表名：

```text
plugins_relationmatchtestanswer
```

字段：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | BigAutoField | 是 | 答案 ID |
| `test` | FK(RelationMatchTest) | 是 | 所属测试 |
| `participant_type` | CharField | 是 | `user` / `visitor` |
| `user` | FK(User, null=True) | 否 | 登录用户，访客为空 |
| `participant_name` | CharField(30) | 是 | 展示昵称；登录用户为账户昵称快照 |
| `visitor_token_hash` | CharField(128, null=True) | 否 | 访客 Cookie 哈希 |
| `is_deleted` | BooleanField | 是 | 管理员软删标记 |
| `created_at` | DateTime | 是 | 提交时间 |

约束：

- 登录用户：同一 `test + user` 只能有一条未删除答卷。
- 未登录访客：同一 `test + visitor_token_hash` 只能有一条未删除答卷。
- `participant_name` 必须存提交时快照。

### 3.5 `RelationMatchTestAnswerItem`

约定表名：

```text
plugins_relationmatchtestansweritem
```

字段：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | BigAutoField | 是 | 条目 ID |
| `answer` | FK(RelationMatchTestAnswer) | 是 | 所属答卷 |
| `question` | FK(RelationMatchQuestion) | 是 | 对应题目 |
| `selected_options` | JSONField | 是 | 该题选择结果，单选存单个 ID，多选存 ID 数组 |
| `dimension_payload` | JSONField | 是 | 该题对八维的贡献明细 |
| `created_at` | DateTime | 是 | 创建时间 |

约束：

- 首版普通前台不暴露该表详情。
- 后台可以查看该表用于追溯和统计。

### 3.6 `RelationMatchProfile`

约定表名：

```text
plugins_relationmatchprofile
```

字段：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | BigAutoField | 是 | 画像 ID |
| `participant_type` | CharField | 是 | `user` / `visitor` |
| `user` | FK(User, null=True) | 否 | 登录用户 |
| `participant_name` | CharField(30) | 是 | 画像展示名 |
| `visitor_token_hash` | CharField(128, null=True) | 否 | 访客哈希 |
| `test` | FK(RelationMatchTest) | 是 | 来源测试 |
| `dimension_scores` | JSONField | 是 | 八维分数，键为维度标识，值为 1-10 |
| `summary_text` | TextField | 是 | 单人画像短段落 |
| `share_code` | CharField(20, unique=True) | 是 | 短匹配码 |
| `share_token` | CharField(80, unique=True) | 是 | 私密链接 token |
| `created_at` | DateTime | 是 | 生成时间 |
| `updated_at` | DateTime | 是 | 更新时间 |

约束：

- 每个用户首版仅保留一份画像。
- 访客同一浏览器首版也只保留一份画像。
- 画像生成后可通过分享链接和短码访问。

### 3.7 `RelationMatchPairResult`

约定表名：

```text
plugins_relationmatchpairresult
```

字段：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | BigAutoField | 是 | 结果 ID |
| `profile_a` | FK(RelationMatchProfile) | 是 | 参与者 A 画像 |
| `profile_b` | FK(RelationMatchProfile) | 是 | 参与者 B 画像 |
| `relation_type` | CharField(50) | 是 | 固定关系类型标识 |
| `subtitle` | CharField(80) | 是 | 关系副标题 |
| `summary_a` | TextField | 是 | A 的短摘要 |
| `summary_b` | TextField | 是 | B 的短摘要 |
| `role_a` | CharField(50) | 是 | A 在关系里的角色 |
| `role_b` | CharField(50) | 是 | B 在关系里的角色 |
| `dimension_compare` | JSONField | 是 | 八维双向对比数据 |
| `relation_explain` | TextField | 是 | 关系说明文字 |
| `highlight_text` | TextField | 是 | 相处亮点 |
| `advice_text` | TextField | 是 | 相处建议 |
| `share_token` | CharField(80, unique=True) | 是 | 结果链接 token |
| `created_at` | DateTime | 是 | 生成时间 |

约束：

- 同一 `profile_a + profile_b` 只允许一份结果。
- 顺序不敏感，`A+B` 与 `B+A` 必须视为同一对。
- 结果创建后不得修改核心内容。

### 3.8 `RelationMatchPairResultMember`

用于结果页双方可见性和访问控制。

字段：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | BigAutoField | 是 | ID |
| `result` | FK(RelationMatchPairResult) | 是 | 所属结果 |
| `profile` | FK(RelationMatchProfile) | 是 | 成员画像 |
| `access_token_hash` | CharField(128, null=True) | 否 | 可选访问校验哈希 |
| `created_at` | DateTime | 是 | 创建时间 |

首版结果链接即授权，但字段保留以便后续扩展。

### 4.2 `RelationMatchDimensionScore`

```json
{

  "care": 9,
  "dependence": 4,
  "empathy": 8,
  "romance": 3,
  "playfulness": 6,
```

### 4.3 `RelationMatchProfileSummary`

```json
{
  "id": 1,
  "participant_type": "user",
  "participant_name": "Alice",
  "user": { "user_id": 1, "username": "alice", "nickname": "Alice", "avatar_url": null },
  "dimension_scores": {
    "dominance": 7,
    "care": 9,
    "dependence": 4,
    "empathy": 8,
    "romance": 3,
    "playfulness": 6,
    "stability": 9,
    "maturity": 8
  },
  "summary_text": "你更像一个稳定、会照顾人的参与者。",
  "share_code": "482913",
  "share_url": "/profile/1/plugins/relation-match?shareCode=482913"
}
```

`share_url` 生成规则（画像链接）：

| 参与者类型 | 生成规则 |
|------------|----------|
| 登录用户 | `/profile/{user_id}/plugins/relation-match?shareCode={share_code}` |
| 未登录访客 | `/plugins/relation-match/join?shareCode={share_code}` |

说明：

- 访客画像不存在 `user_id`，严禁回退到画像自身 `id` 拼装用户主页链接（否则链接 404）。
- 访客画像链接必须指向独立落地路由 `/plugins/relation-match/join`。

```json
{
  "id": 1,

  "relation_explain": "...",
  "highlight_text": "...",
  "advice_text": "...",
  "share_url": "/plugins/relation-match/pairs/1/"

```

`share_url` 生成规则（结果链接）：

```text

```

说明：

- 结果链接统一使用独立路由，不依赖任何参与者 `user_id`，保证访客参与的结果也能被直接打开。

### 4.5 `RelationMatchHome`

```json
{
  "has_profile": true,
  "profile": {
    "id": 1,
    "participant_name": "Alice",
    "share_code": "482913",
    "share_url": "/profile/1/plugins/relation-match?shareCode=482913"
  },
  "entry_text": "看看你们像什么",
  "start_test_url": "/profile/1/plugins/relation-match/tests/current/",
  "history": {
    "total": 2,
    "page": 1,
    "page_size": 20,
    "results": [
      {
        "pair_id": 10,
        "relation_type_name": "死党型",
        "subtitle": "能一起闹，也能一起稳下来",
        "other_participant_name": "Bob",
        "result_url": "/plugins/relation-match/pairs/10/",
        "created_at": "2026-07-12T12:00:00Z"
      }
    ]
  }
}
```

说明：

- `RelationMatchHome` 同时用于插件主页（`users/{owner_id}/`）和我的画像页（`my/`）。
- `profile.share_url` 遵循 §4.3 的画像链接生成规则（访客为独立落地路由）。
- `history.results[].result_url` 遵循 §4.4 的结果链接生成规则（独立路由）。
- 访客答题前 `history` 为空对象；答题并参与匹配后，`history` 展示其匹配记录。

## 5. 前台 API 契约

### 5.1 获取插件主页数据

```text
GET /api/v1/plugins/relation-match/users/{owner_id}/
```

权限：允许未登录。

返回：插件主页状态，包含：

- 是否已有画像
- 分享链接
- 短匹配码
- 邀请中状态
- 匹配历史入口（登录用户）

响应数据必须符合 `RelationMatchHome`。

说明：

- 该接口是插件主页数据入口，必须带 `owner_id`。
- 关系匹配的个人画像状态和分享入口都在插件主页内展示，不存在独立画像页。
- 访客的画像状态不在本接口返回（本接口返回的是主页主人的状态），访客通过 `my/` 接口查看自己的状态（见 §5.7）。

### 5.2 获取基础测试详情

```text
GET /api/v1/plugins/relation-match/tests/current/
```

权限：允许未登录。

规则：

- 只允许访问 `published` 测试。
- 返回题目，但不返回任何评分规则和关系类型映射细节。
- 未登录访客若没有 Cookie，后端必须设置 `fmh_relation_visitor_id`。

说明：

- 该接口是单例接口，前端不得自行拼接测试 ID。
- 所有用户始终进入同一套基础测试。

### 5.3 提交基础测试

```text
POST /api/v1/plugins/relation-match/tests/current/submissions/
```

权限：允许未登录。

请求体：

```json
{
  "participant_name": "秋天的风",
  "share_code": "482913",
  "answers": [
    {
      "question_id": 11,
      "selected_option_ids": [101]
    }
  ]
}
```

说明：

- 登录用户忽略 `participant_name`，使用账户昵称快照。
- 访客必须传 `participant_name`。
- `share_code` 可选：从分享链接或他人主页入口进入答题时携带来源分享码，用于答完后自动匹配。
- 单选题 `selected_option_ids` 只能有 1 个值。
- 多选题可有多个值。

成功响应：返回画像信息、后续邀请入口，以及（可能出现的）自动匹配结果。

响应数据必须包含：

| 字段 | 说明 |
|------|------|
| `profile` | 新生成或更新后的画像摘要 |
| `next_action` | 下一步动作，固定为 `invite` 或 `match` |
| `share_code` | 画像短码 |
| `share_url` | 画像分享链接 |
| `result_url` | 可选；答完自动匹配成功时返回结果页链接 |

成功响应示例（答完即匹配成功，直出结果）：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "profile": {},
    "next_action": "match",
    "share_code": "482913",
    "share_url": "/plugins/relation-match/join?shareCode=482913",
    "result_url": "/plugins/relation-match/pairs/12/"
  }
}
```

成功响应示例（无来源分享码，先到自己的插件主页）：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "profile": {},
    "next_action": "invite",
    "share_code": "482913",
    "share_url": "/plugins/relation-match/join?shareCode=482913"
  }
}
```

说明：

- `share_url` 遵循 §4.3 的画像链接生成规则：登录用户为 `/profile/{user_id}/plugins/relation-match?shareCode={share_code}`，访客为 `/plugins/relation-match/join?shareCode={share_code}`。
- 提交方是访客时，响应中的 `share_url` 必须指向独立落地路由，严禁回退到画像自身 `id` 拼装用户主页链接。
- 携带 `share_code` 且来源画像已存在时：答完后自动匹配，返回 `result_url`，前端直接跳转结果页（`next_action` 为 `match`）。
- 未携带 `share_code`（或来源画像不存在）时：不自动匹配，前端跳转到自己的插件主页（登录用户为插件主页，访客为 `/plugins/relation-match/my`，`next_action` 为 `invite`）。

### 5.4 发起匹配

```text
POST /api/v1/plugins/relation-match/shares/{share_code}/match/
```

权限：允许未登录。

请求体：

```json
{
  "participant_name": "秋天的风"
}
```

规则：

- 如果当前访问者还没有画像，先走基础测试流程。
- 如果已存在画像，直接进入匹配。
- 若同一对画像已生成结果，直接返回已有结果。

说明：

- 该接口只负责“用当前访问者画像和分享码对应画像生成/获取关系结果”。
- 不承担基础测试本身的加载职责。

成功响应必须返回 `RelationMatchPairResultDetail`。

### 5.5 获取关系结果

```text
GET /api/v1/plugins/relation-match/pairs/{result_id}/
```

权限：允许未登录。

规则：

- 只要拿到结果链接即可访问完整报告。
- 返回 `RelationMatchPairResultDetail`。

响应数据必须符合 `RelationMatchPairResultDetail`。

### 5.6 获取我的历史

```text
GET /api/v1/plugins/relation-match/my/pairs/
```

权限：允许未登录。

返回：分页结果，包含当前参与者（登录用户或当前浏览器访客）参与过的关系报告。点击任一项必须直接进入对应关系结果页。

- 登录用户：按账户返回历史。
- 未登录访客：按 `fmh_relation_visitor_id` Cookie 哈希识别，返回该访客参与过的匹配记录。

`results` 的元素必须符合 `RelationMatchHistoryItem`。

历史列表排序规则：

1. 按 `created_at` 从新到旧。
2. 若存在同一结果被再次访问，不重复出现。

### 5.7 获取我的画像状态

```text
GET /api/v1/plugins/relation-match/my/
```

权限：允许未登录。

返回：当前参与者（登录用户或当前浏览器访客）自己的插件主页状态，响应数据必须符合 `RelationMatchHome`。

规则：

- 登录用户：返回本人画像状态与匹配历史。
- 未登录访客：按 `fmh_relation_visitor_id` Cookie 哈希识别，返回该访客自己的画像状态与匹配历史；无 Cookie 时后端先生成并设置 Cookie，再返回空状态。
- 访客未答题时 `has_profile` 为 `false`，`share_code`/`share_url` 为 `null`。
- 访客答题后即拥有自己的插件主页，`history` 展示其参与过的匹配记录（若有）。

说明：

- 该接口是"我的画像页"数据入口（见 §10.2），用于答题完成后展示当前参与者自己的画像状态、短码、分享链接与匹配历史。
- 不依赖 `owner_id`，也不要求当前访问者是任何用户。

### 5.8 获取分享落地信息

```text
GET /api/v1/plugins/relation-match/shares/{share_code}/
```

权限：允许未登录。

返回：分享码对应的画像摘要，用于分享落地页展示分享人昵称。响应数据必须符合 `RelationMatchProfileSummary`。

规则：

- 分享码不存在时返回 40004。
- 只返回公开画像摘要，不返回答题细节和内部算法。
- 该接口不要求访问者已有画像，未答题访客也可打开落地页。

说明：

- 该接口是独立落地路由 `/plugins/relation-match/join` 的数据入口，用于展示“是谁邀请的”。
- 配对本身仍走 §5.4 的 `POST /shares/{share_code}/match/`。

## 7. 算法契约

### 7.1 计分原则

| 规则 | 说明 |
|------|------|
| 维度范围 | 1-10 |
| 计分方式 | 多维权重 |
| 题目覆盖 | 按场景覆盖八维 |
| 类型判断 | 先按固定类型优先，再补副标题和解释 |

### 7.2 维度映射

每道题的每个选项都可以对一个或多个维度赋权。权重由后端固定配置，不对前台暴露。

### 7.3 结果类型生成

关系类型必须基于双方画像的组合结果生成，不允许前台手动选择关系类型。

首版原则：

1. 先计算双方八维差异与共性。
2. 再落入固定关系类型之一。
3. 再生成副标题、双方摘要、角色解释和建议。

### 7.4 同一对唯一性

| 规则 | 说明 |
|------|------|
| 用户对唯一 | 同一用户和同一对象只生成一份关系结果 |
| 顺序无关 | A+B 与 B+A 视作同一对 |
| 再次访问 | 返回已有结果，不重新生成 |

- 展示当前参与者自己的画像状态、短码与分享入口。

- 从 `?shareCode=` 读取分享码。
- 未登录访问者先三分流：登录 / 注册 / 以访客身份继续。

- 分享人自己打开自己的链接：回到自己的插件主页（访客为 `/plugins/relation-match/my`，登录用户为插件主页）。

- 逐题翻页答题。
- 未登录访客填写昵称。
- 支持登录后继续。
- 提交后生成画像。
- 提交时携带来源 `share_code`（从分享链接或他人主页入口进入时）。
- 提交响应含 `result_url`：前端直接跳转结果页。
- 提交响应 `next_action` 为 `invite`（无来源分享码或来源画像不存在）：登录用户跳转自己的插件主页，访客跳转 `/plugins/relation-match/my`。

#### `RelationMatchPairResultPage.vue`

- 展示双方名字。
- 展示关系类型和副标题。
- 展示八维雷达图和双向对比。
- 展示双方摘要、亮点和建议。
- 首屏提供结果链接分享入口，强调可分享。
- 结果链接统一为独立路由 `/plugins/relation-match/pairs/:pairId`。
- 提供"我的主页"按钮，点击进入自己的插件主页（登录用户为插件主页，访客为 `/plugins/relation-match/my`）。

## 14. 安全与隐私

### 14.1 标准答案保护

以下接口不得返回题目权重和内部算法细节：

- 插件主页接口
- 测试答题接口
- 画像获取接口
- 关系结果接口
- 历史列表接口

管理员接口可以查看逐题答案和统计。

### 14.2 结果访问

结果链接即授权，持有链接即可查看完整报告。

结果链接统一为独立路由 `/plugins/relation-match/pairs/{result_id}/`，不依赖任何参与者用户身份。

### 14.3 访客保护

- 不保存访客 Cookie 明文。
- 访客昵称只做展示，不作为强唯一身份。
- 访客画像链接不得回退到画像自身 `id` 拼装用户主页链接。
- 首版接受轻风险，不做复杂反爬和风控强化。

## 15. 测试用例清单

### 15.1 测试与画像

- 登录用户可以完成 40 题基础测试。
- 访客可以填写昵称并完成 40 题基础测试。
- 基础测试完成后生成画像。
- 画像生成后可通过分享码访问。

### 15.2 匹配

- 未完成测试的另一方可从分享链接进入并先答题。
- 已有画像的另一方可以直接匹配。
- 同一对画像只生成一次关系结果。
- 重复打开结果链接直接进入结果页。
- 访客画像的 `share_url` 为独立落地路由 `/plugins/relation-match/join`，不得回退到画像自身 `id`。
- 访客从分享链接答题，提交携带 `share_code`，答完自动匹配并直接进入结果页（响应含 `result_url`）。
- 访客从主页入口答题且主人已答完：答完自动匹配，直接进入结果页。
- 访客从主页入口答题且主人未答完：答完进入自己的插件主页（`my/`），等待主人答完后再匹配。
- 未登录访问者打开落地页先三分流：登录 / 注册 / 访客继续。
- 访客答完通过 `my/` 能看到自己的画像状态、短码、分享链接与匹配历史。
- 登录用户打开自己的画像链接回到自己的插件主页；访客打开自己的画像链接回到 `/plugins/relation-match/my`。

### 15.3 结果

- 结果页展示双方名字、关系类型、副标题、雷达图、对比、摘要、亮点、建议。
- 结果链接可以无登录查看。
- 结果 `share_url` 为独立路由 `/plugins/relation-match/pairs/{result_id}/`。
- 结果不展示负面判词。
- 结果页首屏提供结果链接分享入口。
- 结果页提供"我的主页"按钮，可进入自己的插件主页。

### 15.4 通知与后台

- 登录用户生成关系结果后双方都收到通知。
- 访客生成结果不通知。
- 管理员可查看画像、匹配、逐题答案和统计数据。

## 16. 实施注意事项

- 不要把结果做成单人排行榜。
- 不要把逐题答案暴露给普通前台。
- 不要把访客昵称当作唯一身份。
- 不要在结果页引入负面判词。
- 不要允许同一对画像重复生成多份关系结果。
- 不要把分享图作为首版依赖。
- 不要在首版开放删除或隐藏结果。
