# 默契问答插件重构产品需求文档

> 版本: v1.0  
> 状态: 已收敛待开发  
> 面向读者: 产品、设计、前端、后端、测试  
> 适用范围: FallingMapleHaven 默契问答插件重构  
> 核心结论: 默契问答从“好友互相出单题”重构为“主页主人创建测试，访客参与答题”的主页测验插件。

---

## 1. 背景与目标

### 1.1 当前问题

当前默契问答插件实现为“登录用户向好友单独出题，好友作答后计算两人匹配度”。该模式不符合本次客户需求。

客户期望的默契问答应是围绕个人主页展开的互动测试：主页主人创建测试，其他用户或访客进入主页后答题，答完后立即看到成绩，并进入该测试的答卷榜。

### 1.2 重构目标

本次重构目标如下：

| 目标 | 说明 |
|------|------|
| 玩法重构 | 从“好友互相出题”改为“主页测验” |
| 访客参与 | 未登录访客也可以参与答题 |
| 主人配置 | 主页主人可以创建、保存草稿、发布自己的默契测试 |
| 单选测试 | 首版固定为 10 道单选题 |
| 即时结果 | 答题提交后立即展示成绩 |
| 答卷榜 | 每套测试有独立公开答卷榜，作为结果页和分享落点 |
| 温暖体验 | UI 延续枫落港温暖卡片风格，兼顾移动端答题和桌面端管理 |

### 1.3 非目标

以下内容不在首版范围内：

| 功能 | 首版处理 |
|------|----------|
| 好友互相出题 | 不再作为本次主玩法 |
| 好友全局排行榜 | 暂不做 |
| 跨测试排行榜 | 暂不做 |
| 逐题答卷详情展示 | 首版不展示，但保留后续扩展可能 |
| 主人删除单条答卷 | 首版不做 |
| 用户自定义题审核 | 首版不审核 |
| 用户举报测试或题目 | 首版不做 |
| 动态分享 | 首版不做，仅复制 URL 分享 |
| 前台题库分类展示 | 后续再做 |
| 账号注销/封禁后的特殊处理 | 后续再定 |

## 2. 术语定义

| 术语 | 定义 |
|------|------|
| 主页主人 | 创建并发布默契测试的用户，即个人主页的所有者 |
| 参与者 | 回答某套默契测试的人，可以是登录用户，也可以是未登录访客 |
| 未登录访客 | 未登录系统但可以访问公开测试并答题的人 |
| 测试 | 主页主人创建的一套默契问答，首版固定包含 10 道单选题 |
| 题目 | 测试中的一道单选题 |
| 选项 | 单选题的可选答案，首版每题 2-4 个选项 |
| 标准答案 | 主页主人创建题目时选择的自己的答案，用于和参与者答案比对 |
| 答卷 | 参与者对某套测试提交的一次完整作答记录 |
| 答卷榜 | 某一套测试下所有答卷的公开排名列表，也是答完题后的结果落点页面 |
| 系统题库 | 管理员维护的样例题库，主页主人可以从中挑选题目并复制到自己的测试中 |
| 草稿 | 主人创建但未发布的测试，访客不可见 |
| 发布 | 测试通过校验后对外可见并可答题 |
| 软删除 | 测试前台下线，但历史数据在后台保留 |

## 3. 角色与权限

### 3.1 角色

| 角色 | 能力 |
|------|------|
| 主页主人 | 创建测试、保存草稿、发布测试、复制分享链接、查看答卷榜、软删除测试 |
| 登录参与者 | 进入他人测试答题、使用账户昵称提交、查看结果、出现在答卷榜、查看“我答过的” |
| 未登录访客 | 输入昵称后答题、查看结果、出现在答卷榜 |
| 管理员 | 维护系统题库、查看测试和答卷、删除违规内容、查看统计数据 |

### 3.2 参与权限

| 场景 | 权限规则 |
|------|----------|
| 访问测试邀请链接 | 只检查测试是否处于发布状态 |
| 从主页进入测试 | 只展示该主页主人已发布的测试 |
| 登录用户答题 | 使用账户昵称，不需要额外填写昵称 |
| 未登录访客答题 | 需要填写本次展示昵称 |
| 重复答题 | 首版同一参与者同一套测试只能答一次 |
| 主页入口 | 默契问答入口始终展示 |

### 3.3 重复答题判定

首版重复答题规则如下：

| 参与者类型 | 判定方式 |
|------------|----------|
| 登录用户 | `user_id + test_id` 限制每套测试只能提交一次 |
| 未登录访客 | `visitor_token(cookie) + test_id` 限制同一浏览器每套测试只能提交一次 |

补充说明：

- 未登录访客的昵称仅用于展示，不作为强唯一身份。
- 不以 IP 作为主要唯一判断依据。
- 同一设备上，未登录访客答过一次后，登录用户仍可以用自己的账号再答一次。
- 首版允许“体验级防重复”，不承诺强防刷。

## 4. 核心玩法

### 4.1 玩法概述

主页主人创建最多 3 套默契测试。每套测试固定 10 道单选题。主页主人为每题设置自己的标准答案。其他用户或未登录访客进入测试后作答，系统将参与者答案与主页主人的标准答案比对，计算答对题数和正确率，并根据分数展示称号。

### 4.2 核心规则

| 规则项 | 首版规则 |
|--------|----------|
| 每个主页主人测试数量 | 最多 3 套 |
| 每套测试题目数量 | 固定 10 道 |
| 题型 | 单选题 |
| 每题选项数 | 2-4 个 |
| 标准答案 | 创建题目时由主页主人设置 |
| 草稿 | 允许不足 10 题保存 |
| 发布 | 必须正好 10 题、每题 2-4 选项、每题有标准答案 |
| 发布后编辑 | 不允许编辑题目、选项和标准答案 |
| 答题结果 | 提交后立即展示 |
| 标准答案展示 | 不向参与者展示主页主人的标准答案 |
| 排行榜范围 | 仅限单套测试内的答卷榜 |

## 5. 页面与板块设计

### 5.1 页面总览

首版包含 5 类页面或板块。

| 编号 | 页面/板块 | 主要用户 | 说明 |
|------|-----------|----------|------|
| 1 | 个人主页插件入口卡片 | 所有人 | 进入默契问答插件的入口 |
| 2 | 默契问答插件页 | 所有人 | 包含我的测试、答卷榜、我答过的 |
| 3 | 创建/编辑测试页 | 主页主人 | 创建草稿、编辑题目、发布测试 |
| 4 | 测试答题页 | 登录参与者、未登录访客 | 逐题翻页答题 |
| 5 | 答卷榜页面 | 所有人 | 单套测试的公开排名列表，也是答完后的结果落点 |

### 5.2 个人主页插件入口卡片

位置：个人主页插件区。

入口始终展示，即使主页主人尚未发布测试。

展示内容：

| 元素 | 内容 |
|------|------|
| 插件名称 | 默契问答 |
| 入口文案 | 来测测你有多了解我 |
| 操作 | 点击进入默契问答插件页 |

行为：

| 访问者 | 点击行为 |
|--------|----------|
| 主页主人 | 进入自己的默契问答插件页，可创建和管理测试 |
| 登录访客 | 进入该主页主人的默契问答插件页 |
| 未登录访客 | 进入该主页主人的默契问答插件页 |

### 5.3 默契问答插件页

约定路径：

```text
/profile/:userId/plugins/quiz
```

该页面是默契问答插件的主页。首版包含 3 个 Tab 或板块。

| 板块 | 可见对象 | 说明 |
|------|----------|------|
| 我的测试 | 主页主人 | 管理自己创建的测试，包含草稿和已发布测试 |
| 答卷榜 | 所有人 | 查看某套测试的公开答卷排名 |
| 我答过的 | 登录用户 | 查看当前登录用户答过的测试 |

非主页主人访问该页面时，页面应重点展示该主页主人已发布的测试列表。若没有已发布测试，展示空状态：

```text
TA 还没有发布测试
```

### 5.4 我的测试板块

仅主页主人可见。

功能：

| 功能 | 说明 |
|------|------|
| 创建测试 | 页面主按钮入口 |
| 查看测试列表 | 展示草稿和已发布测试 |
| 保存草稿 | 创建未完成时可保存 |
| 发布测试 | 通过发布校验后对外可见 |
| 复制测试邀请链接 | 复制单套测试答题页链接 |
| 复制答卷榜链接 | 复制单套测试答卷榜链接 |
| 查看答卷榜 | 进入对应测试的答卷榜页面 |
| 删除测试 | 软删除，前台下线，历史数据保留 |

测试卡片展示字段：

| 字段 | 说明 |
|------|------|
| 测试标题 | 主人填写 |
| 状态 | 草稿 / 已发布 |
| 题目数量 | 草稿可能不足 10，发布后固定 10 |
| 答卷数量 | 当前测试累计提交答卷数 |
| 操作按钮 | 编辑草稿、发布、复制链接、查看答卷榜、删除 |

### 5.5 创建/编辑测试页

采用单页编辑，不做分步向导。

页面结构：

| 区域 | 内容 |
|------|------|
| 顶部操作区 | 测试标题、保存草稿、发布按钮、状态提示 |
| 题库入口 | 从系统题库挑选样例题 |
| 题目编辑区 | 题卡纵向排列 |
| 发布校验区 | 发布失败时展示具体问题 |

题卡字段：

| 字段 | 规则 |
|------|------|
| 题目文案 | 必填，发布时不能为空 |
| 选项 | 2-4 个，发布时必须满足 |
| 标准答案 | 必填，必须从当前题目选项中选择 |

题库使用规则：

- 主页主人可以从系统题库挑选样例题。
- 选中题库题后，系统将题目复制到当前测试中。
- 复制后的题目属于该测试的副本。
- 主人可以修改复制后的题目文案和选项。
- 主人仍需为该题设置自己的标准答案。

发布校验规则：

| 校验项 | 规则 |
|--------|------|
| 题目数量 | 必须正好 10 道 |
| 选项数量 | 每题必须 2-4 个选项 |
| 标准答案 | 每题必须设置 |

发布后限制：

- 发布后不可编辑题目。
- 发布后不可编辑选项。
- 发布后不可编辑标准答案。
- 如不想继续开放，只能删除测试，使其前台下线。

### 5.6 测试答题页

约定路径：

```text
/profile/:ownerId/plugins/quiz/tests/:testId
```

答题页采用逐题翻页。

页面结构：

| 区域 | 内容 |
|------|------|
| 顶部 | 测试标题、进度文案、进度条 |
| 中部 | 当前题目卡片 |
| 下部 | 单选选项 |
| 底部 | 上一题、下一题、提交按钮 |

进度展示示例：

```text
第 3 / 10 题
```

交互规则：

| 行为 | 规则 |
|------|------|
| 选择答案 | 点击选项后高亮当前选择 |
| 下一题 | 当前题未选择时不可进入下一题 |
| 上一题 | 允许返回修改尚未提交的答案 |
| 提交 | 第 10 题完成后显示提交按钮 |
| 重复访问 | 如果已答过该测试，不允许重复提交 |

未登录访客进入答题页时，必须先填写本次展示昵称。

登录用户进入答题页时，自动使用账户昵称，不需要填写昵称。

### 5.7 答卷榜页面

答卷榜页面是某一套测试下所有答卷的公开排名列表，也是用户答完题后的跳转页面。

约定路径：

```text
/profile/:ownerId/plugins/quiz/tests/:testId/leaderboard
```

页面含义：

| 参数 | 说明 |
|------|------|
| ownerId | 主页主人，即测试创建者 |
| testId | 某一套具体测试 |
| leaderboard | 该测试下所有答卷的结果排名列表 |

页面结构：

| 区域 | 内容 |
|------|------|
| 我的结果卡 | 当前参与者刚提交或自己的结果摘要 |
| 答卷榜列表 | 当前测试下所有答卷的公开排名 |

我的结果卡展示：

| 字段 | 示例 |
|------|------|
| 答对题数 | 8 / 10 |
| 正确率 | 80% |
| 称号 | 很懂 TA |
| 分享按钮 | 复制答卷榜链接 |

答卷榜列表展示：

| 字段 | 说明 |
|------|------|
| 排名 | 根据成绩排序 |
| 昵称 | 登录用户昵称或访客填写昵称 |
| 登录状态 | 登录用户 / 访客 |
| 答对题数 | 例如 8 / 10 |
| 正确率 | 例如 80% |
| 称号 | 根据成绩生成 |

排序规则：

1. 按正确率从高到低排序。
2. 因为首版固定 10 题，正确率和答对题数等价。
3. 正确率相同时，显示并列排名。
4. 并列排名下，列表内部按提交时间从早到晚展示，但不影响名次。

当前答卷高亮：

- 用户答完题后跳转到答卷榜。
- 页面顶部显示“我的结果卡”。
- 榜单中高亮当前用户或访客刚提交的那条答卷。
- 可通过 `answerId` 参数定位当前答卷。

示例路径：

```text
/profile/:ownerId/plugins/quiz/tests/:testId/leaderboard?answerId=123
```

首版不展示内容：

- 不展示主页主人的标准答案。
- 不展示逐题答题详情。
- 不展示每题对错明细。

## 6. 用户流程

### 6.1 主页主人创建、发布、分享测试

角色：主页主人，已登录。

流程：

1. 用户进入自己的个人主页。
2. 点击主页上的“默契问答”插件卡片。
3. 进入自己的默契问答插件页。
4. 默认进入或选择“我的测试”板块。
5. 点击页面顶部“创建测试”主按钮。
6. 进入创建测试页。
7. 输入测试标题。
8. 从系统题库挑选样例题，或自定义题目和选项。
9. 每道题设置 2-4 个选项。
10. 每道题设置自己的标准答案。
11. 如果未满 10 题，可以保存为草稿。
12. 草稿显示在“我的测试”中，仅主人可见。
13. 补齐到固定 10 题后点击发布。
14. 系统校验：正好 10 题、每题 2-4 个选项、每题有标准答案。
15. 校验失败时，页面提示具体问题并定位到对应题卡。
16. 校验通过后，测试变为发布状态。
17. 发布后的测试出现在该主页的默契问答测试列表中。
18. 用户可以复制测试邀请链接。
19. 用户可以复制答卷榜链接。
20. 发布后题目、选项、标准答案不可再编辑。
21. 如需下线，用户可以删除测试。
22. 删除为软删除：前台下线，历史数据保留。

### 6.2 登录用户从主页进入并答题

角色：答题人，已登录。

流程：

1. 登录用户 A 访问用户 B 的个人主页。
2. A 看到 B 主页上的“默契问答”插件入口卡片。
3. A 点击插件卡片。
4. 进入 B 的默契问答插件页。
5. 如果 B 没有发布测试，页面显示“TA 还没有发布测试”。
6. 如果 B 有发布测试，页面展示 B 的可参与测试列表。
7. A 选择一套测试。
8. 进入测试答题页。
9. 系统自动使用 A 的账户昵称。
10. A 逐题回答 10 道单选题。
11. A 点击提交答案。
12. 系统检查 A 是否已经答过这套测试。
13. 如果已答过，阻止重复提交。
14. 如果未答过，保存答卷。
15. 系统将 A 的答案与 B 设置的标准答案比对。
16. 系统计算答对题数、正确率和称号。
17. 系统跳转到该测试的答卷榜页面。
18. 答卷榜顶部展示 A 的“我的结果卡”。
19. 答卷榜中高亮 A 的本次答卷。
20. 因为 A 是登录用户，系统给 B 发送站内通知。
21. 通知点击后进入该测试的答卷榜页面。
22. A 可以在自己的“我答过的”板块看到该答题记录。

### 6.3 登录用户从测试邀请链接进入并答题

角色：答题人，已登录。

流程：

1. 用户 A 打开用户 B 分享的测试邀请链接。
2. 系统判断该测试是否存在且处于发布状态。
3. 如果测试未发布、已删除或不存在，显示测试不可用。
4. 如果测试已发布，进入测试答题页。
5. 系统自动使用 A 的账户昵称。
6. A 逐题回答 10 道单选题。
7. A 提交答案。
8. 系统检查 A 是否已答过该测试。
9. 如果已答过，阻止重复提交。
10. 如果未答过，保存答卷并计算结果。
11. 系统跳转到该测试答卷榜页面。
12. 页面顶部展示 A 的结果卡。
13. 榜单中高亮 A 的答卷。
14. 系统给测试主人 B 发送站内通知。

### 6.4 登录用户从答卷榜链接进入

角色：登录用户。

流程：

1. 用户打开某套测试的答卷榜分享链接。
2. 系统进入该测试的答卷榜页面。
3. 用户可以查看该测试下的公开排名列表。
4. 如果用户未答过该测试，页面可以提供“去答题”入口。
5. 如果用户已答过该测试，页面可以高亮其历史答卷。

### 6.5 未登录访客从主页进入并答题

角色：未登录访客。

流程：

1. 访客访问用户 B 的个人主页。
2. 访客看到“默契问答”插件入口卡片。
3. 访客点击插件卡片。
4. 进入 B 的默契问答插件页。
5. 如果 B 没有发布测试，页面显示“TA 还没有发布测试”。
6. 如果 B 有发布测试，页面展示可参与测试列表。
7. 访客选择一套测试。
8. 进入测试答题页。
9. 系统要求访客输入本次展示昵称。
10. 系统读取或生成 `visitor_token` Cookie。
11. 访客逐题回答 10 道单选题。
12. 访客点击提交答案。
13. 系统用 `visitor_token + test_id` 判断该浏览器是否已答过。
14. 如果已答过，阻止重复提交。
15. 如果未答过，保存答卷。
16. 答卷保存访客填写的昵称和 Cookie 标识。
17. 系统计算答对题数、正确率和称号。
18. 系统跳转到该测试答卷榜页面。
19. 页面顶部展示访客的结果卡。
20. 榜单中高亮访客刚提交的答卷。
21. 未登录访客提交后，不给主页主人发送站内通知。

### 6.6 未登录访客从测试邀请链接进入并答题

角色：未登录访客。

流程：

1. 访客打开测试邀请链接。
2. 系统判断测试是否处于发布状态。
3. 如果测试未发布、已删除或不存在，显示测试不可用。
4. 如果测试已发布，进入测试答题页。
5. 系统要求访客输入昵称。
6. 系统读取或生成 `visitor_token` Cookie。
7. 访客逐题完成 10 道单选题。
8. 访客提交答案。
9. 系统判断该浏览器是否已答过。
10. 如果未答过，保存答卷并计算结果。
11. 系统跳转到该测试答卷榜页面。
12. 页面顶部展示访客的结果卡。
13. 榜单中高亮访客答卷。
14. 不通知主页主人。

## 7. 结果与评分

### 7.1 评分规则

每道题只有一个标准答案。参与者选择的答案与主页主人设置的标准答案一致，则该题计为正确。

公式：

```text
答对题数 = 参与者答案与标准答案一致的题目数量
正确率 = 答对题数 / 10 * 100%
```

示例：

```text
答对 8 题，则显示 8 / 10，正确率 80%
```

### 7.2 称号规则

首版称号文案写死，不提供后台配置。

固定分段：

| 答对题数 | 正确率 | 称号 |
|----------|--------|------|
| 10 | 100% | 灵魂拍档 |
| 8-9 | 80%-90% | 很懂 TA |
| 6-7 | 60%-70% | 默契在线 |
| 4-5 | 40%-50% | 还要多聊聊 |
| 0-3 | 0%-30% | 神秘距离感 |

首版必须使用以上固定分段和固定称号文案。

### 7.3 结果展示规则

| 内容 | 是否展示 |
|------|----------|
| 答对题数 | 展示 |
| 正确率 | 展示 |
| 称号 | 展示 |
| 当前答卷在榜单中的排名 | 展示 |
| 标准答案 | 不展示 |
| 逐题对错 | 不展示 |
| 每题作答详情 | 不展示 |

## 11. UI/UX 设计要求

### 11.1 设计方向

整体风格确定为“温暖卡片”。

设计关键词：

- 温暖
- 轻社交
- 卡片式
- 清晰可信
- 有一点仪式感，但不过度游戏化

视觉要求：

- 延续枫落港 maple 色系。
- 主背景使用柔和浅色。
- 内容使用白色卡片承载。
- 使用圆角、轻阴影、柔和边框。
- 使用 lucide 图标，不使用 emoji 作为结构性图标。
- 结果称号用文字强化，不依赖夸张动效。

### 11.2 设备优先级

移动端和桌面端同等重要。

| 场景 | 重点 |
|------|------|
| 移动端 | 答题、打开分享链接、查看结果 |
| 桌面端 | 创建测试、管理测试、后台维护 |

### 11.3 答题体验

答题采用逐题翻页。

要求：

- 一次只展示一道题。
- 顶部显示进度条和题号。
- 选项按钮触控区域不小于 44px 高。
- 当前已选选项必须有明显视觉状态。
- 下一题按钮在当前题未选择时禁用。
- 支持上一题返回修改未提交答案。
- 提交时显示加载状态，防止重复点击。

### 11.4 创建测试体验

创建测试采用单页编辑。

要求：

- 页面顶部固定或显著展示保存草稿、发布按钮。
- 10 道题以题卡形式纵向排列。
- 每张题卡内完成题目、选项、标准答案编辑。
- 发布失败时必须明确提示具体哪一题缺失或不合法。
- 发布后进入只读状态，不允许编辑题目、选项和标准答案。

### 11.5 结果与答卷榜体验

答完题后跳转到答卷榜页面。

页面顶部必须展示“我的结果卡”。

我的结果卡应突出：

- 答对题数。
- 正确率。
- 称号。
- 分享按钮。

答卷榜应：

- 高亮当前答卷。
- 展示排名和成绩。
- 不展示标准答案。
- 不展示逐题详情。

### 11.6 空状态

| 场景 | 文案 |
|------|------|
| 主页主人没有发布测试 | TA 还没有发布测试 |
| 主人自己的测试列表为空 | 还没有创建默契测试，先创建一套吧 |
| 答卷榜为空 | 还没有人完成测试 |
| 我答过的为空 | 你还没有答过默契测试 |

### 11.7 交互与无障碍

要求：

- 所有按钮必须有可见文字或可访问标签。
- 表单字段必须有明确 label，不能只依赖 placeholder。
- 错误提示必须靠近对应字段。
- 所有可点击区域满足移动端触控尺寸。
- loading 状态必须禁用重复提交。
- 删除测试前必须二次确认。
- 不通过颜色单独表达选中或错误状态，需配合文字、边框或图标。
